Atmospheres are **CSS decoration overlays** that sit on top of a client's Tokens Dimension to establish visual character — luxury-editorial, soft-wellness, organic-paper — without duplicating CSS per client. One of the five [Theming Dimensions](/docs/theming), orthogonal to the others. They are mode-agnostic: every atmosphere works on a light page and on a dark one.

The portal's theme generator reads `company_profiles.atmosphere` at extraction time and inlines that atmosphere's CSS (from `@brikdesigns/bds/atmospheres/{slug}.css`) into the stored theme artifact. It does not emit an `@import`. The consumer Astro site fetches one theme artifact at build; the atmosphere cascades automatically.

<Callout type="info">
**Atmospheres are decoration only.** They add vignettes, grain, orbs, and spotlights — they do not set surface colors, and none is tied to light or dark. The only mode-specific rule is the grain blend, keyed to `:root[data-theme="dark"]`. Background and text colors come from the Tokens Dimension (`dist/tokens.css` + the client's `theme-{slug}.css` in `@layer client-theme`). Import `@brikdesigns/bds/page-base.css` after tokens to wire `html/body` background to `var(--page-primary)` before any atmosphere loads.
</Callout>

## How atmospheres compose with themes

| Axis | Where it's set | What it controls |
|---|---|---|
| **Theme tokens** | `design_token_extraction` task reads `company_profiles.color_primitives` + `typography` | Brand palette, fonts, spacing, border-radius |
| **Theme mode** | `company_profiles.theme_mode` (light / dark) | Whether text is dark-on-light or light-on-dark. The only source of light or dark |
| **Atmosphere** | `company_profiles.atmosphere` (this vocab) | Decoration layer — vignettes, grain, orbs, spotlights |
| **Navigation IA** | `pack.navigationIA` (industry default) + portal overrides | Header archetype + scroll + mobile drawer |
| **Expression modes** | `[data-mode-*]` on `:root` | Spacing, radius, type, width, motion |

Each axis is set on its own. A dental practice might pick `theme_mode: dark` + `atmosphere: editorial-luxury` + `navigation: editorial-transparent`; a wellness studio might pick `theme_mode: light` + `atmosphere: warm-soft` + `navigation: calm-flat`. Any atmosphere pairs with either mode: a dark client with `warm-soft` is valid. The full resolution order and who writes each value are in [Client Themes § How the website builder's picks resolve to a mode](/docs/theming/client-themes#how-the-website-builders-picks-resolve-to-a-mode).

## Vocabulary

The locked enum lives in `content-system/vocabularies/atmosphere.ts`.

| Slug | Grain blend (light / dark) | Natural fit |
|---|---|---|
| `editorial-luxury` | multiply / overlay | dental · med-aesthetic · luxury hospitality |
| `cinematic-dramatic` | no grain | legal · agency · finance · SaaS |
| `warm-soft` | multiply / screen | wellness · therapy · mental-health · recovery |
| `organic-textured` | multiply / screen | MUA · organic beauty · artisan · natural products |
| `none` | no grain | explicit no-op — fallback when atmosphere is null |
| `minimal-clinical` | deprecated | emits nothing — use `none` |
| `clean-bright` | deprecated | emits nothing — use `none` |

<Callout type="warn">
`minimal-clinical` and `clean-bright` are deprecated and will be removed in `1.0.0` (`DEPRECATED_ATMOSPHERES` in `content-system/vocabularies/atmosphere.ts`). Both emit zero CSS, so they are two names for `none`. Migrate stored `company_profiles.atmosphere` values to `none` before removal.
</Callout>

## Per-atmosphere reference

Each atmosphere renders on the same compact composite (hero + services grid + CTA) so you can compare treatments side by side. Previews are iframed to isolate atmosphere `:root` / `body` rules from the docs shell — the atmosphere CSS loads verbatim from `@brikdesigns/bds/content-system/atmospheres/{slug}.css`.

### editorial-luxury

Radial orbs (from the brand colour) driven by `data-ambient` attributes on sections; SVG Perlin film grain at 32% opacity with `mix-blend-mode: multiply` on light and `overlay` on dark; cursor-tracking spotlight on elements with `data-spotlight`. Section-edge fades reference `var(--page-primary)` from the theme layer so they blend into whatever surface color the brand sets. Honors reduced-motion.

<AtmospherePreview atmosphere="editorial-luxury" />

### cinematic-dramatic

Aurora-drift gradient at the top of the viewport (42s cycle, animated via `@property` interpolation) and a conic rotating spotlight on sections marked `data-ambient="spotlight"`. No grain — the aurora is already doing the atmospheric work. Section-edge fades reference `var(--page-primary)`. Fit for legal / agency / finance / SaaS.

<AtmospherePreview atmosphere="cinematic-dramatic" />

### warm-soft

Single quiet rose vignette in the top-left corner and subtle grain at 15% opacity with `mix-blend-mode: multiply` on light and `screen` on dark. No motion, no spotlights, no depth orbs — anxiety-sensitive audiences (wellness, therapy, mental health, recovery) shouldn't see cinematic flourish. Section-edge fades reference `var(--page-primary)`.

<AtmospherePreview atmosphere="warm-soft" />

### organic-textured

SVG Perlin grain at 40% opacity with `mix-blend-mode: multiply` on light and `screen` on dark for a tactile, recycled-paper texture. Subtle earth-tone radial tint in the bottom-right. Fit for MUA / organic beauty / artisan / natural-products brands where tactile materiality matters more than digital polish.

<AtmospherePreview atmosphere="organic-textured" />

### none

Explicit no-op. Emits no rules. Fallback when `company_profiles.atmosphere` is null or a client doesn't want an atmospheric layer. Exists so the portal's theme generator can unconditionally inline an atmosphere without branching.

<AtmospherePreview atmosphere="none" />

## How to pick

When building a new client site:

1. **Read `company_profiles.theme_mode`** (light | dark). It is the client's one base mode; client sites get no light/dark toggle. If it is unset, the design-direction task fills it from the brief's color direction. The order of precedence is in [Client Themes](/docs/theming/client-themes#order-of-precedence).
2. **Read `company_profiles.atmosphere`**. Pick by fit, not by mode — every atmosphere works in both:
   - dental / med-aesthetic / luxury hospitality → `editorial-luxury`
   - legal / agency / finance → `cinematic-dramatic`
   - wellness / therapy → `warm-soft`
   - MUA / beauty / artisan → `organic-textured`
   - no decoration wanted → `none` (never the deprecated `minimal-clinical` or `clean-bright`)
3. **The portal theme generator** inlines the atmosphere CSS into the stored theme CSS; consumer sites pull the theme at build time and the atmosphere cascades automatically. No per-client atmosphere CSS in the consumer repo.
4. **Extending the vocabulary**: new atmospheres go through the BDS PR process — add the slug to `ATMOSPHERE_VALUES`, write a CSS file in `content-system/atmospheres/`, add a manifest entry, extend the `package.json` exports, key any grain blend to `:root[data-theme="dark"]`, and add a preview block to this page. Don't invent atmospheres per client; graduate them.
