**Elevation** is the Figma collection that governs depth. It names six depths: `sunken`, `flat`, `subtle`, `raised`, `lifted` and `dramatic`. The build composes each depth into one ready-to-use `--bds-shadow-{depth}` token, which is what components reference.

<Callout type="warn">
  **Use the composed depth tokens in component CSS** — `--bds-shadow-subtle`, `--bds-shadow-raised`, `--bds-shadow-lifted`, `--bds-shadow-dramatic`. Never compose raw offset, blur and spread values yourself; each depth is tuned in Figma as one unit.
</Callout>

## From Figma Elevation to shadow tokens

A Figma variable holds one value, so each depth is four variables: `shadow/{depth}/offset`, `/blur`, `/spread` and `/color`. Offset, blur and spread alias the `shadow-offset`, `shadow-blur` and `shadow-spread` primitives. The build joins the four into one `box-shadow` value ([#3058](https://github.com/brikdesigns/brik-bds/issues/3058)). Nothing hand-written declares a `--bds-shadow-{depth}`.

| Layer | Names | Where |
|---|---|---|
| Figma primitives | `shadow-offset/*`, `shadow-blur/*`, `shadow-spread/*` | Foundations → `design-tokens/tokens-studio.json` |
| Figma collection | `Elevation` → `shadow/{depth}/{offset,blur,spread,color}` | same |
| Composed (what you use) | `--bds-shadow-{sunken,flat,subtle,raised,lifted,dramatic}` | `tokens/figma-tokens.css` |

The x-offset is always `0`. A depth whose Figma description says `inset` composes as an inner shadow; today that is `sunken`.

<Callout type="info">
  **`--bds-shadow-*` is the only elevation family.** To suppress a shadow write `box-shadow: none`, or use `--bds-shadow-flat` when a depth must stay swappable.
</Callout>

## Depth tokens

| Depth | CSS Variable | Value | Use case |
|---|---|---|---|
| Sunken | `--bds-shadow-sunken` | `inset 0 2px 4px 0 rgba(0,0,0,0.06)` | Wells, recessed fields |
| Flat | `--bds-shadow-flat` | `0 0 0 0 rgba(0,0,0,0)` | No shadow, kept swappable |
| Subtle | `--bds-shadow-subtle` | `0 2px 4px 0 rgba(0,0,0,0.06)` | Controls, toggles, sticky headers |
| Raised | `--bds-shadow-raised` | `0 4px 12px 0 rgba(0,0,0,0.12)` | Cards, panels |
| Lifted | `--bds-shadow-lifted` | `0 4px 16px 0 rgba(0,0,0,0.12)` | Dropdowns, popovers, menus |
| Dramatic | `--bds-shadow-dramatic` | `0 4px 32px 0 rgba(0,0,0,0.24)` | Modals, dialogs, sheets |

<Callout type="info">
  **`dramatic`'s 32px blur is a raw value in Figma.** The `shadow-blur` scale tops out at 16px, so no primitive carries it yet.
</Callout>

### Renamed in #3058

The old hand-written names stay as deprecated aliases for one minor release, then drop.

| Old | New |
|---|---|
| `--bds-shadow-sm` | `--bds-shadow-subtle` |
| `--bds-shadow-md` | `--bds-shadow-raised` |
| `--bds-shadow-lg` | `--bds-shadow-lifted` |
| `--bds-shadow-overlay` | `--bds-shadow-dramatic` |
| `--bds-shadow-xl` | removed — use `--bds-shadow-dramatic` |
| `--bds-blur-radius-*` | removed — no Figma variable behind it |

A consumer that **overrides** an old name must rename the override. BDS components read the new names, so an override of `--bds-shadow-md` no longer reaches them.

## Filter blur

There is no filter-blur token. `filter: blur()` and `backdrop-filter` soften an element, or whatever sits behind it. That is a different job from the blur part of a `box-shadow`. The old `--bds-blur-radius-*` scale was hand-written with no Figma variable behind it, so #3058 removed it.

Until Figma names a backdrop blur, the one user (the Astro `SiteHeader` blueprint) borrows `--bds-shadow-blur-600`, the same 12px.
