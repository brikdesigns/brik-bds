Border tokens frame a component's edge in two axes: **radius** (corner rounding) and **width** (line thickness). Each carries a theme-level mode so a brand can shift the overall feel in one move.

## Border radius

Border radius tokens control corner rounding across components — from sharp (0px) to pill (999px), with `circle` reserved for fully circular elements (avatars, dots).

### Radius scale

<BorderRadiusPreview scale={borderRadiusScale} prefix="--border-radius" />

### Semantic radius tokens

| Token | CSS Variable | Description |
|---|---|---|
| None | `--bds-border-radius-none` | No rounding (0px) |
| Small | `--bds-border-radius-sm` | Subtle rounding |
| Medium | `--bds-border-radius-md` | Default component radius |
| Large | `--bds-border-radius-lg` | Prominent rounding |
| Pill | `--bds-border-radius-pill` | Maximum rounding (999px) |

### Radius modes

`data-mode-radius` on the root element selects a radius mode (default `soft`, the attribute-absent state). The mode rewrites `--bds-border-radius-sm`, `-md` and `-lg`; `none` never changes.

| Mode | Effect | Use case |
|---|---|---|
| Sharp | 2 / 4 / 8px (sm / md / lg) | Corporate, minimal |
| Soft | 8 / 12 / 16px | Default, balanced |
| Round | 16 / 24 / 40px | Friendly, modern |
| Pill | Controls fully round (999px); containers keep the Round ramp (16 / 24 / 40px) | Pill buttons and inputs without stadium-shaped cards |

### Pill is a control shape, not a container shape

Buttons and cards read the same `--bds-border-radius-{sm,md,lg}` tokens, so setting those to 999px at the root turned every Card, Modal, media frame and CTA panel into a stadium. Under `data-mode-radius="pill"` the root therefore carries the bounded Round ramp, and the 999px values are re-bound only inside the control selectors: Button, TextInput, Select and Tag. Containers inherit the root ramp and stay bounded.

- Fully round: `.bds-button`, `.bds-text-input-field`, `.bds-select`, `.bds-tag`.
- Bounded (Round ramp): Card, Modal, MediaTabs, media frames, TextArea (a multi-line field reads as a lozenge at 999px), and everything else.
- To add a control, append its class to `scopedModes.pill.controlSelectors` in `scripts/generate-modes-css.mjs` and regenerate; do not hand-edit `tokens/modes-borderradius.css`.

See the live pair in Storybook: Containers / card, `PillRadiusMode`.

## Border width

Border width tokens control line thickness for borders, dividers, and outlines.

### Width scale

<BorderWidthPreview scale={borderWidthScale} prefix="--border-width" />

### Semantic width tokens

| Token | CSS Variable | Description |
|---|---|---|
| None | `--bds-border-width-none` | No border (0px) |
| Small | `--bds-border-width-sm` | Subtle hairline |
| Medium | `--bds-border-width-md` | Default visible border |
| Large | `--bds-border-width-lg` | Prominent border (3px default; varies by border-width mode) |
| Extra large | `--bds-border-width-xl` | Heavy border (4px default) |
| Huge | `--bds-border-width-huge` | Heaviest border (5px default) |

### Width modes

Border density is a theme-level mode. Set `data-mode-borderwidth` on `:root` (or any subtree) to shift every `--border-width-*` semantic token at once; the default (no attribute) keeps the base values. Two override modes ship — `thin` and `thick`, the Figma mode names — generated into [`tokens/modes-borderwidth.css`](https://github.com/brikdesigns/brik-bds/blob/main/tokens/modes-borderwidth.css):

| Token | `default` | `thin` | `thick` |
|---|---|---|---|
| `--bds-border-width-none` | 0 | 0 | 0 |
| `--bds-border-width-sm` | 0.5px | 0.25px | 1px |
| `--bds-border-width-md` | 1px | 0.5px | 3px |
| `--bds-border-width-lg` | 3px | 1px | 5px |
| `--bds-border-width-xl` | 4px | 2px | 8px |
| `--bds-border-width-huge` | 5px | 3px | 12px |

```html
<html data-mode-borderwidth="thick">   <!-- whole document -->
<section data-mode-borderwidth="thin">…</section>   <!-- one subtree -->
```

`bold` is the retired name for `thick`. It still matches for one release, then stops resolving — switch to `thick`. Values verified against `dist/tokens.css`; after a Figma mode change, re-pull and regenerate with `npm run build:modes`.
