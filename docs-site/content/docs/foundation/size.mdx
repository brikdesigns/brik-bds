## Content widths

**One ladder caps every horizontal width on a page** — text column and band alike — and each rung carries exactly one role, stated in its name. A `-text-` rung caps a **text column**; a bare rung sizes a **band** ([ADR-041](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-041-one-content-width-ladder.md)). Apply with `max-width` on the element that owns the column.

| Token | CSS Variable | Value | Caps | Use for |
|---|---|---|---|---|
| Text XS | `--bds-content-width-text-xs` | 448px | text | Short intro — eyebrow + one-line title |
| Text SM | `--bds-content-width-text-sm` | 600px | text | Section intro — title + description (the default) |
| Text MD | `--bds-content-width-text-md` | 720px | text | Long-form prose, rich-text body |
| Narrow | `--bds-content-width-sm` | 640px | band | Narrow band, focused forms |
| Default | `--bds-content-width-md` | 800px | band | Standard body sections |
| Wide | `--bds-content-width-lg` | 1024px | band | Feature sections, content grids |
| XL | `--bds-content-width-xl` | 1280px | band | Hero bands, wide layouts |
| Full | `--bds-content-width-full` | 100% | band | Full-bleed (use sparingly) |

The text rungs interleave numerically with the band rungs (600 < 640 < 720 < 800). Pick a rung by its **role**, which the name states — never by sorting the ladder.

```css
/* a band */
.content-section {
  max-width: var(--bds-content-width-md);
  margin-inline: auto;
}

/* the text column inside it */
.article-body {
  max-width: var(--bds-content-width-text-sm);
}
```

A column has one content width and one left edge: the element that owns the column sets the width, and blocks nested inside it never re-cap themselves. See [Page Grid → The column rule](/docs/build-standards/page-grid#the-column-rule), which is where the horizontal-axis standard lives — this page is the token catalog.

<Callout type="info">
  There used to be a second `--measure-sm/md/lg` ladder in `ch` for the text column. ADR-041 retired it into the `-text-` rungs above at the px widths it already rendered; the old names ship one more minor as deprecated aliases, then drop — don't reach for them in new code. Nothing in BDS scales body type — `--body-md` is a fixed 16px, only `--display-fluid-*` clamps, and `[data-mode-spacing]` never touches `font-size` — so `ch` never tracked anything, while two siblings sharing one `ch` cap at different type sizes resolved to two different pixel widths.
</Callout>

## Screen breakpoints

BDS defines five canonical breakpoints. All five are Figma variables in the ❖ Brik Foundations `breakpoint` collection, and the CSS custom properties (`--breakpoint-*`) are generated from them. **For CSS `@media` rules inside BDS, use the `--bds-up-*` / `--bds-down-*` custom media below; in TS, import `mediaQueries` (or `breakpoints`) from `@bds-tokens`** — CSS custom properties (`var()`) cannot be used inside `@media()`.

| Name | CSS Variable | Value |
|---|---|---|
| Mobile | `--bds-breakpoint-mobile` | 320px |
| Tablet | `--bds-breakpoint-tablet` | 768px |
| Desktop | `--bds-breakpoint-desktop` | 1024px |
| Wide | `--bds-breakpoint-wide` | 1280px |
| Wider | `--bds-breakpoint-wider` | 1440px |

<Callout type="warn">
**`--breakpoint-web` no longer exists.** A sixth rung named `web` (1200px default / 800px compact / 1400px comfortable) was a legacy layout-width value, never a screen breakpoint, and was retired from the ❖ Brik Foundations library in #2604. Five is the whole ladder.
</Callout>

<Callout type="info">
  **The `--breakpoint-*` CSS custom properties are reference-only by design** (ADR-025 §4). CSS variables can't be read inside `@media()`, so real breakpoint logic goes through the TS exports below — which is why [Token Anatomy → Named exceptions](/docs/foundation/token-anatomy#named-exceptions) records zero `var(--breakpoint-*)` references anywhere. That is an intentional split, not dead weight: the CSS vars carry the values into Figma and the docs, the TS exports carry them into conditions.
</Callout>

The [layout tier](/docs/foundation/spacing#layout-tier) also reads three rungs — `mobile`, `tablet` and `wider` — at build time, as the widths where `--page-inset` and `--section-padding-block` hit their device values. Moving one of those rungs in Figma moves the tier's endpoint with it.

### Using breakpoints in CSS

`mediaQueries` gives ready-made conditions, so a call site never re-derives one. `up.<rung>` is mobile-first (`min-width`); `down.<rung>` is the exclusive complement, stepped down 0.02px so `up` and `down` never both match at the boundary.

```tsx
import { mediaQueries } from '@bds-tokens';

// In a CSS-in-JS context
const styles = {
  [`@media ${mediaQueries.up.desktop}`]: {
    display: 'grid',
    gridTemplateColumns: '1fr 2fr',
  },
};
```

```css
/* In BDS component CSS — a breakpoint custom media, resolved to px at build time */
@media (--bds-up-desktop) {
  .sidebar-layout {
    display: grid;
  }
}
```

The names are `--bds-up-<rung>` (`min-width`, all five rungs) and `--bds-down-<rung>` (`max-width`, rung minus 0.02px; every rung except `mobile`). They live in `tokens/custom-media.css`, and `postcss.config.mjs` resolves each one to px, so `dist/styles.css` ships plain `@media` conditions — `@custom-media` is not Baseline in browsers. `lint-tokens` pins each definition to its `--breakpoint-*` rung and fails any literal px in an `@media` under `components/` ([ADR-044](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-044-breakpoint-custom-media.md)). Consumers are unaffected: they get the resolved px from `dist`.

### Using breakpoints in your own CSS

`@brikdesigns/bds/custom-media.css` ships the same `--bds-up-*` / `--bds-down-*` definitions. A browser can't read `@custom-media`, so run your CSS through [postcss-custom-media](https://github.com/csstools/postcss-plugins/tree/main/plugins/postcss-custom-media) and load the definitions with `@csstools/postcss-global-data`, which keeps them out of your output:

```bash
npm i -D postcss postcss-custom-media @csstools/postcss-global-data
```

```js
// postcss.config.mjs
import { createRequire } from 'node:module';
import postcssGlobalData from '@csstools/postcss-global-data';
import postcssCustomMedia from 'postcss-custom-media';

const customMedia = createRequire(import.meta.url).resolve('@brikdesigns/bds/custom-media.css');

export default {
  plugins: [postcssGlobalData({ files: [customMedia] }), postcssCustomMedia()],
};
```

```css
/* in */
@media (--bds-up-tablet) { .shell { display: grid; } }

/* out */
@media (min-width: 768px) { .shell { display: grid; } }
```

The repo runs this recipe against its own package on every change: `npm run example:consumer-breakpoints` compiles `examples/consumer-breakpoints/input.css` and fails if any custom media is left unresolved.

### Using breakpoints in JavaScript

```ts
import { mediaQueries } from '@bds-tokens';

const isDesktop = window.matchMedia(mediaQueries.up.desktop).matches;
```

`breakpoints` remains exported for the cases where you need the raw width — a `sizes` attribute, a layout calculation, a chart threshold:

```ts
import { breakpoints } from '@bds-tokens';

const px = parseInt(breakpoints.desktop, 10); // 1024
```

## Element sizes

Fixed element dimensions — icons, dots, indicators — use the numeric `--size-*` scale. Values step in 4px increments above 8px.

<Callout type="warn">
  **`--size-*` and `--space-*` are two scales, not one — don't treat `--size-400` and `--space-400` as interchangeable.** They share identical values on the low/mid steps (`0` through `2100`), but they diverge: `--space-*` adds half-steps (`--space-250` = 10px, `--space-350` = 14px, `--space-450` = 18px) and runs higher (to `--space-3000` = 176px), while `--size-*` tops out at `--size-2200` = 100px — and at that shared index the two disagree (`--space-2200` = 104px). Pick by intent: **`--size-*` for a fixed element dimension** (width/height of an icon, dot, indicator), **`--space-*` for layout spacing** (the primitive that `--padding-*` / `--gap-*` draw from). Verify the value in `dist/tokens.css` rather than assuming the same index matches.
</Callout>

| Token | Value |
|---|---|
| `--bds-size-50` | 2px |
| `--bds-size-100` | 4px |
| `--bds-size-200` | 8px |
| `--bds-size-400` | 16px |
| `--bds-size-600` | 24px |
| `--bds-size-800` | 32px |
| `--bds-size-1000` | 40px |

The scale runs `--size-0` (0) through `--size-2200` (100px).

## Shell sizes

Fixed dimensions of the product app shell. Use them for the layout the shell owns — the fixed top bar, the sidebar column, and the section rail — so a consumer never repeats the px.

| Token | Value | Source |
|---|---|---|
| `--bds-shell-top-bar-height` | 64px (`--bds-size-1600`) | Portal top bar height |
| `--bds-shell-sidebar-width` | 260px | `SidebarNavigation` default expanded width |
| `--bds-shell-sidebar-width-collapsed` | 80px (`--bds-size-1800`) | `SidebarNavigation` default collapsed width |
| `--bds-shell-rail-width` | 220px | Section rail (`SubNavigation`) column in the portal |

```css
.shell__rail {
  position: sticky;
  top: var(--bds-shell-top-bar-height);
  width: var(--bds-shell-rail-width);
  height: calc(100vh - var(--bds-shell-top-bar-height));
}
```

Layer the shell with [Stacking order](/docs/foundation/stacking).

## Aspect ratio

`--aspect-*` feeds the `aspect-ratio` property, so a media box holds its shape as it scales — no padding-hack. Nine ratio primitives cover the common orientations, and four semantic aliases name the cases you reach for most.

| Token | CSS Variable | Ratio |
|---|---|---|
| Square | `--bds-aspect-1-1` | 1 / 1 |
| Landscape | `--bds-aspect-4-3` | 4 / 3 |
| Portrait | `--bds-aspect-3-4` | 3 / 4 |
| Landscape (photo) | `--bds-aspect-3-2` | 3 / 2 |
| Portrait (photo) | `--bds-aspect-2-3` | 2 / 3 |
| Portrait (social) | `--bds-aspect-4-5` | 4 / 5 |
| Widescreen | `--bds-aspect-16-9` | 16 / 9 |
| Vertical (stories) | `--bds-aspect-9-16` | 9 / 16 |
| Ultrawide | `--bds-aspect-21-9` | 21 / 9 |

Four aliases point at the primitive above so intent reads at the call site — prefer them where one fits.

| Alias | Resolves to | Names |
|---|---|---|
| `--bds-aspect-square` | `--bds-aspect-1-1` | Avatars, thumbnails |
| `--bds-aspect-cinema` | `--bds-aspect-16-9` | Video, hero media |
| `--bds-aspect-photo-landscape` | `--bds-aspect-3-2` | Landscape photography |
| `--bds-aspect-photo-portrait` | `--bds-aspect-2-3` | Portrait photography |

```css
.media-frame {
  aspect-ratio: var(--bds-aspect-cinema);
}
```
