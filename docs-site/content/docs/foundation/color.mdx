Color tokens define the visual identity across all BDS themes. The system separates **primitive color scales** (raw hex values) from **semantic color roles** (purpose-bound aliases). Components reference the semantic roles only.

<Callout type="warn">
  **Never use a token outside its semantic category.** `--text-*` is for text. `--background-*` is for backgrounds. `--border-*` is for borders. No `--text-primary` on a `background-color`. The cascade is a contract — bypassing it leaks brand drift everywhere it isn't caught.
</Callout>

Click any swatch to copy `var(--token-name)` to your clipboard.

## Accent

The **scope-stable accent** — one brand highlight that stays fixed regardless of `[data-audience]` scope (brik fills it from `tan`; each Brand Kit fills its own). Use it for audience-independent affordances such as an active carousel dot or an eyebrow rule.

It is distinct from two neighbours it is easy to confuse:

- **`--*-brand-primary`** re-tints per audience scope (Vale: land → gold, healthcare → olive). The accent must *not* shift, so it is its own role — not a brand-tier token.
- **The per-color status accents** (`--background-accent-blue`, `--text-accent-green`, …) encode state/category, not the brand highlight.

### The per-hue accent set

Separate from the scope-stable accent above, `accent-{hue}` names a **category color** — six hues for tagging things that have no valence. A calendar's event categories, a chart series, a tag palette.

The set is mirrored 1:1 from the **❖ Brik Brand Kit** Figma library, which is the source of truth for it. Five hues fill from the **system** palette — that is what keeps `accent-purple` the same purple whichever client theme is loaded — and the purpose split is the one the valence families use:

| Purpose | Fills from | Use for |
|---|---|---|
| `--text-accent-{hue}` | `--color-system-{hue}` — the vivid step | Colored label or icon on a neutral surface |
| `--background-accent-{hue}` | `--color-system-{hue}` — the vivid step | A saturated fill: a dot, a solid chip, a chart mark |
| `--border-accent-{hue}` | `--color-system-{hue}` — the vivid step | A hairline or left-rule keyed to the category |
| `--surface-accent-{hue}` | `--color-system-{hue}-light` — the pale tint | A wash behind content: a subtle chip, a callout, a row highlight |
| `--page-accent-{hue}` | `--color-system-{hue}-light` — the pale tint | A full-page or section-wide wash |

**The grid is deliberately not square, because canon isn't.** Two gaps are mirrored from Figma rather than filled in:

- `--page-accent-{hue}` exists for `yellow`, `blue`, `orange` and `red` only — there is no page-level green or purple wash.
- **`red` is the exception to the system-palette rule.** All five of its purposes alias the **brand poppy** (`#e35335`), not `--color-system-red`. So `--surface-accent-red` is a saturated *fill*, not a pale tint like the other five — it is gated AA rather than AAA in [the matrix](/docs/foundation/color-pairings#the-matrix), and small body copy does not belong on it. `Avatar`'s red initials fill is the shipped consumer.

Two consequences worth knowing before you reach for one:

- **Put dark ink on a `surface-accent-{hue}`, not `--text-primary`.** The tints hold the same pale value in both themes while `--text-primary` flips to near-white in dark, which lands at 1.2:1. `--text-on-color-light` is the theme-stable pairing and clears AAA on all five tints (AA on the red fill) — the six `accent` rows in [the matrix](/docs/foundation/color-pairings#the-matrix) gate it.
- **`--text-accent-{hue}` is not a foreground for `--surface-accent-{hue}`.** Same-hue vivid-on-pale only clears AA for `blue`; the other four fall below the 3:1 floor ([#2080](https://github.com/brikdesigns/brik-bds/issues/2080)).

{/* lint-mdx-tokens-ignore-start — the deprecated alias is the subject of this note */}

<Callout type="info">
  `--surface-accent-{hue}` shipped in [#2065](https://github.com/brikdesigns/brik-bds/issues/2065) pointing at the Brand Kit mid-tone ramp (`--color-{hue}-light`, itself a deprecated alias for the `-500` step). [#2066](https://github.com/brikdesigns/brik-bds/issues/2066) re-pointed it onto the system tint, then reconciled the whole family against the Figma Brand Kit — adding `--border-accent-{hue}`, `--page-accent-{hue}` and `--surface-accent-red`, and moving `accent-red` onto the brand poppy. Dark ink on the purple tint went from 5.68:1 to 12.87:1 in the process.
</Callout>

## The 11-step scale

Every family is an **11-step numeric ramp** — `50, 100, 200, … 900, 950`, lightest to darkest. `50` and `950` bracket the ends; the middle nine carry the working values. The scale is **generated, not hand-tuned per family**: `scripts/generate-color-ramps.mjs` pins the six historical swatches as anchors and interpolates the other five stops as OKLCh midpoints, writing `design-tokens/color-ramps.generated.json` ([#1737](https://github.com/brikdesigns/brik-bds/issues/1737)). Shipped in v0.152.0.

Reach for a stop by its number. `--color-{family}-{stop}` is the Primitive-tier name; components still consume Semantic tokens only.

### Deprecated 6-step aliases

The old ladder (`lightest → lighter → light → dark → darker → darkest`) still resolves — [#1739](https://github.com/brikdesigns/brik-bds/issues/1739) aliased each name onto its stop so nothing broke on upgrade. The aliases are **deprecated** and land at these positions in every family:

{/* lint-mdx-tokens-ignore-start — the deprecated names are the subject of this table */}

| Deprecated alias | Resolves to | Anchor? |
|---|---|---|
| `--color-{family}-lightest` | `100` | anchor |
| `--color-{family}-lighter` | `300` | anchor |
| `--color-{family}-light` | `500` | anchor |
| `--color-{family}-dark` | `700` | anchor |
| `--color-{family}-darker` | `800` | anchor |
| `--color-{family}-darkest` | `950` | anchor |

{/* lint-mdx-tokens-ignore-end */}

Note the ladder was never evenly spaced: `dark` and `darker` sit one stop apart (`700`/`800`) while `darker` to `darkest` skips `900`. Prose that said "one step deeper" under the 6-step names does not translate to one numeric stop — count stops, don't translate names.

<Callout type="warn">
  **Don't write a deprecated alias into new code.** `npm run lint-mdx-tokens` fails the build on one in a docs code block or table, and `lint-tokens` Rule 12 covers component CSS. Consumer migration is tracked in [#1740](https://github.com/brikdesigns/brik-bds/issues/1740); the aliases are removed only once it closes.
</Callout>

### The two new stops that matter

Five stops per family are new. Two of them close specific, filed gaps:

| Stop | Value | Why it exists |
|---|---|---|
| `--color-poppy-600` | `#c94428` | **4.84:1 on white — clears AA (4.5:1).** The near-Poppy step [ADR-015](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-015-brand-primary-aa-large-contrast-policy.md)/[ADR-016](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-016-small-primary-button-contrast.md) said did not exist, unblocking [#479](https://github.com/brikdesigns/brik-bds/issues/479) |
| `--color-grayscale-400` | `#b0b0b0` | Fills the `#828282` → `#e0e0e0` gap from [#1726](https://github.com/brikdesigns/brik-bds/issues/1726). It is **not** `#bdbdbd` — no even OKLCh ramp lands there, so consumers that hand-pinned `#bdbdbd` are migrating to this value, not matching it |
