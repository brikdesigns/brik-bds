Motion tokens define how long a transition runs and how it accelerates. They come in two tiers, and neither is a t-shirt ladder:

| Tier | Family | Named by | Figma source |
|---|---|---|---|
| Primitive | `--bds-duration-*` | A numeric step | ❖ Brik Foundations `primitives/value` → `duration/{step}` |
| Semantic | `--bds-ease-*` | Behaviour — out, in, spring | ❖ Brik Foundations `motion/default` → `ease/{name}` |

There is no `--duration-sm` / `-md` / `-lg`. Which duration a transition takes is decided by the [pairing table](#pairing) below, not by a token name ([ADR-033 § Amendments, "Duration has no Semantic tier"](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-033-naming-canon-one-word-per-concept.md)).

## Durations

The numeric primitive scale. Every tween in BDS reads one of these directly.

<Callout type="warn">
  **The numeric suffix is a step index, not a millisecond value.** `--bds-duration-400` is `500ms`, not `400ms`. The suffix tracks milliseconds up to `--bds-duration-300` and then stops. If you reach past `--bds-duration-300`, read the value rather than the name — an animation otherwise lands 25% slower than intended and nothing errors.
</Callout>

| Token | Value | Suffix matches value |
|---|---|---|
| `--bds-duration-100` | `100ms` | yes |
| `--bds-duration-200` | `200ms` | yes |
| `--bds-duration-300` | `300ms` | yes |
| `--bds-duration-400` | `500ms` | **no** |
| `--bds-duration-500` | `800ms` | **no** |
| `--bds-duration-600` | `1000ms` | **no** |

## Easing

The semantic tier. Each curve names a behaviour, so the name says what the motion does rather than how long it lasts.

| Token | Value | Use case |
|---|---|---|
| `--bds-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | Decelerate — entrances and most UI transitions |
| `--bds-ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | Accelerate — exits, collapses |
| `--bds-ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | Symmetric — moving or resizing in place, loops |
| `--bds-ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Overshoot bounce — pop-in, badge appear |
| `--bds-ease-spring-soft` | `cubic-bezier(0, 1.08, 0.77, 1.01)` | Gentle overshoot settle — media/panel entrance (softer than `--bds-ease-spring`) |
| `--bds-ease-linear` | `linear` | Constant velocity — marquees, continuous loops |

<Callout type="info">
  Reach for `--bds-ease-out` / `--bds-ease-in` for ordinary decelerate / accelerate needs — there is deliberately no separate `--ease-decel` / `--ease-accel`. `--bds-ease-spring-soft` is the one exception the house curves did not already cover: a settle that overshoots just past its target without the visible bounce of `--bds-ease-spring`.
</Callout>

## Pairing

A transition is always a duration **and** a curve. Pick the row for the interaction, then use both tokens from it. The rows are what BDS components ship today.

| Interaction | Duration | Ease | Example |
|---|---|---|---|
| Hover or focus on a small target — list item, nav link | `--bds-duration-100` | `--bds-ease-out` | Menu, NavItem, Breadcrumb, Chip |
| Control or card changes state — hover, toggle, select | `--bds-duration-200` | `--bds-ease-out` | Button, Card, Tag, ToggleSwitch |
| Enter — reveal, appear | `--bds-duration-300` | `--bds-ease-out` | Badge, MediaTabs |
| Exit, collapse | `--bds-duration-300` | `--bds-ease-in` | MediaTabs, SyncedMediaSteps |
| Long entrance — media, panel | `--bds-duration-400` | `--bds-ease-spring-soft` | MediaTabs, SyncedMediaSteps |

```css
.bds-example {
  transition: background-color var(--bds-duration-100) var(--bds-ease-out);
}
```

Two rules hold across the table:

- **Exits are no longer than entrances.** An element leaving should get out of the way, so it takes `--bds-ease-in` and never a longer duration than its entrance.
- **Feedback is never delayed by motion.** An error message or focus ring appears at once; animate what follows it, not the signal itself.

If no row fits, add one here before shipping the transition — a pairing that lives only in one component's CSS is how motion drifts.

## Periodic durations

A separate class from the transition durations above. These are not tween lengths — they are the **period of a continuous loop** or the **dwell before a timed advance**, so they live in seconds and carry a role name rather than a step ([ADR-033 § Named exceptions](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-033-naming-canon-one-word-per-concept.md), the same basis as `--shadow-overlay`). Only continuous or auto-advancing motion uses these.

| Token | Value | Use case |
|---|---|---|
| `--bds-duration-marquee` | `55s` | Full marquee loop period — logo tickers, continuous scroll |
| `--bds-duration-autoplay` | `10s` | Dwell before auto-advance — carousels, media tabs |

Defined in `tokens/gap-fills.css`. Measured from inspiration teardowns; re-run the Playwright capture before treating a value as canon later — vendor sites drift.

## Stagger

Fixed offsets for sequencing a group of elements into view — apply an increasing stagger as `animation-delay` across siblings.

| Token | Value |
|---|---|
| `--stagger-1` | `0ms` |
| `--stagger-2` | `50ms` |
| `--stagger-3` | `100ms` |
| `--stagger-4` | `150ms` |
| `--stagger-5` | `200ms` |
| `--stagger-6` | `250ms` |

<Callout type="info">
  Stagger tokens ship in `dist/bridge.css`, **not** `dist/tokens.css`. They sit outside the canonical token registry, so a consumer that imports only the token bundle will not have them.
</Callout>

## Where these live

| Token group | Source | Editable |
|---|---|---|
| `--bds-duration-100` … `--bds-duration-600`, all `--bds-ease-*` | Figma → `design-tokens/tokens-studio.json` → `tokens/figma-tokens.css` | Figma only — the CSS is auto-generated |
| `--bds-duration-marquee`, `--bds-duration-autoplay` | Figma `motion` collection → `tokens/figma-tokens.css` | Figma only — loop periods, a named exception to the tween ramp |
| `--stagger-1` … `--stagger-6` | `tokens/compat/bridge.css` | Hand-authored |

Ready-made utility classes built on these tokens — `.bds-enter-*`, `.bds-anim-*` — live in `tokens/motion-classes.css` over the keyframes in `tokens/animations.css`. Prefer an existing class before writing a new animation.
