Card is the canonical content-grouping container. A default flexible mode, plus four arrangements selected by the `layout` prop:

- **Default** — flexible container, compose with `CardTitle` / `CardDescription` / `CardFooter` subcomponents.
- **`layout="stack"`** — vertical content card and the malleable cell of a card-grid Section.
- **`layout="row"`** — horizontal content card, media left and text right.
- **`layout="metric"`** — compact stat tile, label above a large value.
- **`layout="control"`** — settings/integration row, media + text left, status + action right.

One flat slot set (`media` / `overline` / `title` / `children` / `action` / `badge`) serves all four, per [ADR-038](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-038-card-anatomy-over-preset-union.md).

<Callout type="warn">
  **The `preset` prop has been removed.** `preset="control" | "summary" | "display" | "display-row"` is replaced by `layout` (ADR-038 §5). See [Migrating off `preset`](#migrating-off-preset) for the mapping.
</Callout>

## Use it for

- Service grids, feature cards, and content blocks (`layout="stack"`)
- Settings panels with title + description + toggle/action (`layout="control"`)
- Dashboard stat tiles ($48K Q1 revenue, 142 active users) (`layout="metric"`)
- Any grouped-content surface where consistent border/padding/shadow matter

For a horizontal stack of card-like rows, use [FieldGrid](/docs/components/field-grid) wrapping Cards. For loading-state placeholders, use [Skeleton](/docs/components/skeleton) `variant="rectangular"`.

## Import

```tsx
import { Card, CardTitle, CardDescription, CardFooter } from '@brikdesigns/bds';
```

## Default mode

Compose freely with the Title / Description / Footer subcomponents. Omit `layout` entirely.

```tsx
<Card variant="outlined" padding="md">
  <CardTitle>Title</CardTitle>
  <CardDescription>Description text goes here.</CardDescription>
  <CardFooter>
    <Button variant="primary" size="sm">Action</Button>
  </CardFooter>
</Card>
```

### Variants

- **`outlined`** (default) — Subtle secondary border.
- **`brand`** — Primary-color border for emphasis.
- **`elevated`** — Surface-primary fill, no border, no shadow (flat since brik-bds#1146; for a shadow use `raised`).
- **`raised`** — Surface-primary fill, no border, with a cast `--box-shadow-md` drop shadow. The shadow-casting counterpart to the now-flat `elevated`; use for a focal/lone card or a grid cell that needs a lifted, contained read.
- **`borderless`** — Transparent fill, no border, no shadow. Use for cards sitting on a colored surface, where the border ring reads as visual noise.

The `layout` arrangements take the grid-cell subset — `borderless`, `elevated`, `raised` — so one option set covers every surface treatment.

### Padding

`none`, `sm`, `md` (default), `lg`. Match content density.

### Interactive + link

`interactive` adds hover affordance. `href` renders as an `<a>` so the whole card becomes a link.

```tsx
<Card variant="elevated" interactive>
  Hover me
</Card>

<Card href="/articles/foo" interactive>
  Whole card is a link
</Card>
```

### Leading media

In default mode the `media` prop takes a `CardMedia` object and turns the card into a horizontal "media object" — an `Avatar`, a square 1:1 `Image`, or a bundled `Logo` on the left, with `children` stacked to the right. Pass exactly one of `avatar` / `image` / `logo`. All size to the shared Avatar scale (`sm` 32px, `md` 40px, `lg` 48px, `xl` 64px). The avatar falls back to initials from `name` and can carry a presence `status`; the image takes `fit` (`contain` for logos, `cover` for photos).

```tsx
<Card media={{ avatar: { name: 'Jordan Lee', status: 'online', size: 'lg' } }}>
  <CardTitle as="h4">Jordan Lee</CardTitle>
  <CardDescription>jordan.lee@brikdesigns.com</CardDescription>
</Card>

<Card media={{ image: { src: '/brik-logo.svg', alt: 'Brik Designs logo', fit: 'contain', size: 'lg' } }}>
  <CardTitle as="h4">Brik Designs</CardTitle>
  <CardDescription>Design system · Enterprise plan</CardDescription>
</Card>
```

Under a `layout`, `media` is a plain `ReactNode` instead — pass the `<Frame>`, `<Avatar>`, `<Logo>`, or `<ServiceTag>` you want rendered.

## Stack layout

`layout="stack"` is the vertical content card and the malleable **cell of a card-grid Section**. Every slot is optional and independently toggled, so one arrangement serves any content type — service, blog post, customer story, property listing, team bio, support plan.

```tsx
<Card
  layout="stack"
  overline={<ServiceTag line="brand" />}
  media={<Frame ratio="16-9"><img src="/service.jpg" alt="" /></Frame>}
  badge={<Badge>Featured</Badge>}
  title="Brand identity"
  action={<Button href="/services/branding" variant="outline" size="sm">Learn more</Button>}
>
  Logo, type, and color systems built to scale.
</Card>
```

`title` renders as `titleAs` (default `h3`) — set it to keep the document outline correct under a grid-section heading; the visual size is token-driven and unchanged by the level. For a cell on a colored (service-tinted) grid, `variant="borderless"` (transparent), `variant="elevated"` (fill + shadow), or `variant="raised"` (fill + cast `--box-shadow-md` shadow) swaps the surface treatment, and `tint` applies a pale service-line wash. `badge` renders only when `media` is also set.

`mediaTreatment` controls how the media slot meets the card edge. `flush` (default) bleeds the media to the edge and pads only the body — the blog/story/product-grid look. `inset` frames media and body together in a single inset — the service-card look.

## Row layout

`layout="row"` is the **horizontal** content card and card-grid section row — media on the left, the text column (`overline`, `title`, body, `action`) on the right. Use for single-row sections where a vertical layout wastes horizontal space: Related Customer Story, Recommended Add-On, featured plan. Collapses to a vertical stack at ≤ 640px.

```tsx
<Card
  layout="row"
  overline={<Tag>Case study</Tag>}
  media={<Frame ratio="4-3"><img src="/story.jpg" alt="" /></Frame>}
  imageWidth="standard"
  title="How Northwind tripled conversions"
  action={<Button href="/stories/northwind" variant="outline" size="sm">Read the story</Button>}
>
  A ground-up rebrand and site rebuild.
</Card>
```

`imageWidth` sets the left column: `narrow` (25%), `standard` (35%, default), or `wide` (50%) — or pass any CSS length/percentage string (`"40%"`, `"320px"`).

## Metric layout

`layout="metric"` is the compact stat tile — an `overline` label above a large `title` value, with an optional trailing `action`. Context-neutral: a revenue figure, an active-user count, a storage total. Pre-format the value; the card applies no numeric formatting.

```tsx
<Card
  layout="metric"
  overline="Q1 revenue"
  title="$48,250.75"
  action={<TextLink href="/revenue">Details</TextLink>}
/>
```

Two optional slots extend `metric` for a labelled selection — the shape the removed `ProductSummaryCard` component covered before it folded into this layout (ADR-038 §4). `media` renders a leading glyph beside the stat, and `detail` renders a secondary line below the value. Both are additive, so a plain stat omits them.

```tsx
<Card
  layout="metric"
  media={<ServiceTag category="brand" variant="icon" size="lg" serviceName="Logo Design" />}
  overline="Interested in"
  title="Standard Logo Design"
  detail="$650 • one time"
/>
```

## Control layout

`layout="control"` is the canonical settings and integration row. Leading `media` (logo) plus `title` and `description` on the left; `connectionStatus` indicator and `action` on the right.

```tsx
<Card
  layout="control"
  media={<Logo set="integration" name="notion" />}
  title="Email notifications"
  description="Send a weekly digest to your inbox."
  action={<Button variant="outline" size="sm">Configure</Button>}
/>
```

`actionAlign` controls vertical alignment of the trailing block — `center` (default) or `top`, which anchors to the upper-right when descriptions are tall. `connectionStatus` accepts `not-configured`, `connected`, `syncing`, `synced`, or `failed` and renders a status indicator alongside the action; pass `lastSynced` for a timestamp beneath it.

<Callout type="info">
  **`layout="control"` replaces the standalone `<CardControl>` component**, which is deprecated per [ADR-004](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-004-component-bloat-guardrails.md) ([#657](https://github.com/brikdesigns/brik-bds/issues/657)). New code should use the layout; see the [CardControl migration guide](/docs/components/card-control#migration).
</Callout>

## Migrating off preset

The `preset` discriminator predated ADR-038 and has been **removed** (ADR-038 §5). Use `layout`; the mapping below is for updating any code still on the old union.

| Removed | Replacement | Slot mapping |
|---|---|---|
| `preset="display"` | `layout="stack"` | `image` → `media`, `tag` → `overline`, `description` → `children` |
| `preset="display-row"` | `layout="row"` | same as `stack`, laid out horizontally |
| `preset="summary"` | `layout="metric"` | `label` → `overline`, `value` → `title`; pre-format the value |
| `preset="control"` | `layout="control"` | `logo` → `media`, other slots unchanged |
| `<ProductSummaryCard>` | `layout="metric"` | `media` = `<ServiceTag>`, `overline` = label, `title` = value, `detail` = `price • frequency` |

Two behavior notes on the way across:

- **`preset="summary"` formatted numbers for you** via `type="numeric" | "price"`. `layout="metric"` does not — pass an already-formatted string.
- **`variant` had two option sets** under the union (the default shape's five, the display presets' three). Under `layout` there is one set; the arrangements accept `borderless`, `elevated`, and `raised`.

## When *not* to use

- **Don't use Card for inline content blocks.** Cards imply discrete grouping; for paragraphs and section dividers, use prose + [Divider](/docs/components/divider).
- **Don't use Card for tables.** Use a table component when rows share columns. Cards are for self-contained groupings.
- **Don't reach for the default mode when a `layout` fits.** The layouts carry locked-down anatomy that propagates consistently across screens.

## Accessibility

- Default Card renders a `<div>`; with `href`, it renders an `<a>` with full anchor semantics (right-click, keyboard, screen-reader link role).
- `interactive` without `href` adds `role="button"` only when `onClick` is also passed; otherwise it's a non-interactive hover affordance.
- `title` renders as `titleAs` (default `h3`) under a `layout`, and as an `<h3>` in the `CardTitle` subcomponent — adjust the surrounding heading hierarchy accordingly.

## API

### Default mode

{/* props-check: CardProps @ components/ui/Card/Card.tsx */}
| Prop | Type | Default |
|---|---|---|
| `variant` | `'outlined' \| 'brand' \| 'elevated' \| 'raised' \| 'borderless'` | `'outlined'` |
| `padding` | `'none' \| 'sm' \| 'md' \| 'lg'` | `'md'` |
| `interactive` | `boolean` | `false` |
| `href` | `string` | — |
| `media` | `CardMedia` (exactly one of avatar / image / logo) | — |
| `children` | `ReactNode` *(required)* | — |

### Layout modes

One flat slot set serves all four arrangements. A slot that a layout does not render is ignored rather than type-rejected — the per-layout notes below the table say which is which.

{/* props-check: CardProps @ components/ui/Card/Card.tsx */}
| Prop | Type | Default |
|---|---|---|
| `layout` | `'stack' \| 'row' \| 'metric' \| 'control'` *(required)* | — |
| `media` | `ReactNode` | — |
| `overline` | `ReactNode` | — |
| `title` | `ReactNode` | — |
| `titleAs` | `'h2' \| 'h3' \| 'h4'` | `'h3'` |
| `children` | `ReactNode` | — |
| `action` | `ReactNode` | — |
| `badge` | `ReactNode` | — |
| `variant` | `'borderless' \| 'elevated' \| 'raised'` | — |
| `tint` | `CardTint` (service line) | — |
| `href` | `string` | — |
| `imageWidth` | `CardDisplayRowImageWidth` (narrow / standard / wide, or any CSS length) | `'standard'` |
| `mediaTreatment` | `'flush' \| 'inset'` | `'flush'` |
| `description` | `ReactNode` | — |
| `actionAlign` | `'center' \| 'top'` | `'center'` |
| `connectionStatus` | `'not-configured' \| 'connected' \| 'syncing' \| 'synced' \| 'failed'` | — |
| `lastSynced` | `string` | — |
| `detail` | `ReactNode` | — |

Slots by layout:

| Layout | Renders |
|---|---|
| `stack` | `media`, `overline`, `title`, `children`, `action`, `badge`, `tint`, `variant`, `mediaTreatment`, `href` |
| `row` | the `stack` set plus `imageWidth`, minus `mediaTreatment` |
| `metric` | `media`, `overline`, `title`, `detail`, `action` |
| `control` | `media`, `title`, `description`, `action`, `actionAlign`, `connectionStatus`, `lastSynced` |

All modes accept standard `<div>` HTML attributes (excluding `title`, which is repurposed by the layouts and the control layout).
