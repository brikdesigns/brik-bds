# Brik Design System

The live component playground. Every story renders the actual component with interactive controls, theme switching, and visual-regression baselines.

Narrative docs, usage guides, and API reference live at **[design.brikdesigns.com](https://design.brikdesigns.com)**.

## Two vocabularies — check which one you need

BDS has two structural vocabularies. They are **different axes**, not synonyms, and confusing them is the single most common source of wrong component choices.

| Axis | Question it answers | Vocabulary | Authority |
|---|---|---|---|
| **Composition layer** | How do I reason about this piece of structure? | Blueprint → Layout → Container → Block → Component | [composition-layers](https://design.brikdesigns.com/docs/build-standards/composition-layers) (ADR-030 §36-38) |
| **Storybook taxonomy** | Where does this story file? | the sidebar sections below | ADR-006 Part A, as amended |

The two do not line up one-to-one:

- **`Block` is a composition layer, not a sidebar section.** ADR-006 retired the `Blocks/` bucket on 2026-07-29 and re-titled its members into `Components/`.
- **`Cards` is a sidebar section, not a composition layer.** A Card *is* a Container; the bucket exists on the 2026-07-22 name-family precedent (#1330) because the card family is large and cohesive enough that discoverability beats taxonomic purity.
- **`Blueprint` is the page-section layer** — the only thing that composes a page. `composition-layers` formerly called this layer "Section"; ADR-037 §5 renamed it so the layer and the sidebar section share one word.

One sentence, if you only remember one thing:

> **Blueprints compose the page. Containers hold collections. Blocks fill containers. Layouts arrange. Components are atoms.**

## Install

```ts
import { Button, Card, Sheet } from '@brikdesigns/bds';
```

```css
@import '@brikdesigns/bds/tokens.css';
@import '@brikdesigns/bds/styles.css';
```

Client sites are **Astro**; sites with a CMS or database are **Next.js** (ADR-037 §1). Astro consumers import blueprints from the `blueprints-astro` subpath:

```ts
import { CardGrid, CtaDarkCentered, HeroInteriorMinimal } from '@brikdesigns/bds/blueprints-astro';
```

Astro blueprint export names are still **block + layout** (`CtaDarkCentered`, `HeroSplit6040`), while the React side names by **block** with layout as a prop (`<Cta layout="default">`). ADR-037 § Amendments ratified unifying these onto the React shape; until [#2302](https://github.com/brikdesigns/brik-bds/issues/2302) lands, use the names above — `Hero` and `Cta` are not Astro exports.
