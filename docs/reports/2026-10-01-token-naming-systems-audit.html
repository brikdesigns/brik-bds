Verdict. Agents invent token formulas because the canon page contradicts itself, live code shows them a third grammar, no gate checks names, and the tools agents actually load don't state the formula. RAG works but is barely read for token work.

The ID layer cannot be a leading prefix as stated. --bds- already means a Tier-4 Component token (token-anatomy.mdx:78, ADR-014), so --bds-color-poppy-500 would parse as component color, property poppy-500. Recommended alternative: put the ID inside the Primitive {family} segment, following the --color-system-* precedent that already ships.

3. Root cause, ranked

  1. Canon contradicts itself. Agents have to fill the {family} gap themselves. Three agents filled it three ways.
  2. Live code teaches a different grammar. ✔ The portal emitter writes bare --color-${seg}-lightest|lighter|dark|darker|darkest (brik-client-portal/src/lib/theming/generate-theme-css.ts:989-994). It also writes --${slug}-${seg} (:493-547, e.g. --vale-partners-olive-hover). theme-tncld.css (14 --tncld-*) and theme-brik-portal.css (32 --portal-*) are hand-authored. Figma group names leak straight into tokens (tokens-studio.json:417-436 → tokens.css:45-50).
  3. No gate parses names. lint-tokens.js:654 skips --bds-*. lint-token-tiers.mjs:117 only asks whether a name starts with --color-. The hook ignores anything outside its five families. Invented names pass.
  4. The tools agents actually load don't state the formula (§2), and the design-system agent points at a file that doesn't exist.
  5. The governance ADRs aren't ratified. ADR-014 and ADR-034 are still Proposed, which gives agents licence to suggest alternatives.

The collision

A leading --bds- ID on every token makes --bds-color-poppy-500 parse as Tier-4 {component}=color, {property}=poppy-500 (token-anatomy.mdx:78, ADR-014). Either the Tier-4 namespace gets renamed (2,563 defs across every consumer), or the ID can't be a leading prefix.

Recommended grammar (medium-high confidence)

Primitive: --color-{family}-{step}
           {family} := [{id}-]{hue}    id from a closed registry: system, vale, tncld, portal, birdwell …
                                       BDS's own primitives carry no id
           --color-poppy-500 (BDS)  ·  --color-vale-olive-500 (tenant)  ·  --color-system-yelp (exists)
Semantic:  unchanged — --background-brand-primary; a tenant overrides VALUES under the same names
Component: unchanged — --bds-{component}-{property}

NEW PROPOSALS in this grammar: (a) define {family} and {step} in the segment table (#2666 AC-1/3); (b) keep the ID registry as a closed list in tokens/. No new tier, no new prefix, and --bds- stays as it is.

Blast radius: 0 BDS renames in dist/tokens.css, plus 6 annotation fixes at the Figma source. One-file rewrite of the portal emitter (generate-theme-css.ts:493-547, 985-995), then regenerate vale. Hand renames: tncld (14) and portal (32). Style Dictionary is untouched. The three lint prefix lists learn the registry. Reversible: names change, values don't.
