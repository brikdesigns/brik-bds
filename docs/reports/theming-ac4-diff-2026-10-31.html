Theming AC4: Client-Site Diff for the Foundation-Leak Fix

Date: 2026-10-31 · Issue: brik-bds#2910 AC4 · Umbrella: brik-bds#2851 · Change under test: PR #2913 (8fe4e3f1, merged to main, not released) · Baseline: @brikdesigns/bds@0.217.0 (npm latest at time of run)

Verdict (HIGH confidence): releasing #2913 changes no rendered pixel on Birdwell Mutlak, Rebel CFO or Vale Partners. All 54 of 54 built pages were checked in light and dark mode. 107 of 108 captures were compared; the one left out is a redirect stub. Every compared capture shows 0 changed pixels, except Vale's home page, which plays a video hero and stays inside its own capture noise (see the control). No page paints Brik's Poppy palette after the change.

Open call (operator): AC4 go, i.e. may the next BDS release ship #2913? A release changes what client sites build against, so it waits for your go. #2913 merged to main on 2026-10-30, before this AC4 ran, so the next BDS release ships it whether or not this call is made first.

1. Method

  • Each site's origin/main was checked out in a detached worktree, and its prebuild (theme fetch) ran once, so both builds share the same theme inputs.
  • Base: the site was built with BDS 0.217.0 from npm. Candidate: the site was built with a tarball of BDS main 8fe4e3f1 (build:lib and check:esm both exited 0).
  • Site commits: birdwell-mutlak 5b97307, rebel-cfo 84d6b5d, vale-partners 6b22905.
  • Population: every index.html in each built dist/, giving Birdwell 36, Rebel 4 and Vale 14 pages. Vale's two Google site-verification .html files are not pages and were excluded.
  • Per page and per colour scheme, Playwright Chromium rendered a 1280px-wide full-page screenshot, with animations off and reduced motion. A pixel counted as changed when any channel moved by more than 8. Every custom property was also resolved on <html> and <body>, and each brand, accent or page slot was resolved to its painted colour.
  • Positive control (the build really differs): the first :root block of dist/tokens.css contains Poppy 24 times in 0.217.0 and 0 times in main. On every page, 400 to 426 custom properties resolve differently and 88 to 153 brand slots paint differently. The candidate is therefore a different token cascade, not a rebuild of the same one.
  • Noise control (the diff can see change): Vale home, base build captured against itself, gave 0.410% (light) and 3.492% (dark) changed pixels, all from its <video> hero.

3. Latent Risk: Unbound Brand Slots Change Colour, Unseen

None of these slots paint on any measured page today. If a future section uses one without the site's theme binding it, the colour shown changes from Brik's Poppy to the Foundation grayscale. Neither colour is the client's brand, so the bug of an unbound slot already existed before #2913; the release only changes the colour it shows. The values below are for light mode.

AGENT DECIDED (revisable): this is not a release blocker. Evidence: 0 changed pixels across the population, and the slots were already off-brand before the change. Revert: treat it as a blocker and bind each site's brand slots before release. Binding them is the remaining work in #2851 (steps 5 and 6).

4. Not Covered

  • Other consumers of BDS (brikdesigns.com, the portal, other client sites) were not built. This AC covers the three sites #2910 names.
  • Only a 1280px viewport was tested. The token change is not viewport-dependent, but a narrow-only section that uses an unbound slot would not appear here.
  • Interactive states (hover, focus, open menus) were not driven. -hover brand slots do move (see §3).
