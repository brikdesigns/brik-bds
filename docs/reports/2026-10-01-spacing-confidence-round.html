Strongest counter-evidence: GOV.UK

GOV.UK does vary some spacing inside a component by viewport. I checked each case against source this session:

  • components/button/_mixin.scss:218-229: .govuk-button__start-icon uses margin-left: govuk-spacing(1), then govuk-spacing(2) from desktop.
  • components/accordion/_mixin.scss:58-59: govuk-responsive-padding(3, "top") / (8, "bottom").
  • components/footer/_mixin.scss:15-16: govuk-responsive-padding(7, "top") / (5, "bottom").

Why this doesn't change D2. The button case is a step jump between two fixed tokens. That is exactly the case Carbon allows. The accordion and footer cases use GOV.UK's responsive scale, a mixin that picks a value per breakpoint. BDS can express the same thing, a component choosing a different fixed token at a breakpoint, without any token becoming device-moded. So the remaining question is not "do we allow it?" It is "where does the breakpoint come from?" The answer is the breakpoint collection, which the operator asked to keep.

4. New conflict found: --page-inset already has density modes

tokens/gap-fills.css:514-516 gives --page-inset compact 16, comfortable 32 and spacious 48. If it also became the device-moded margin, one token would take both axes, which breaks the rule D1 proposes.

Recommend (high): the layout tier owns --page-inset, and its density ladder is removed. Today no consumer sets data-mode-spacing (09-30 report, §5), so removing the ladder changes no rendered page. The ADR records this.

6. Operator decisions

  1. Canonical Figma desktop frame. section-intro and section-stages give 104 vertical / 96 inline. section-full-stack gives 88 / 64.
    Recommend: 104 / 96, since 2 of 3 frames use it. The ladders become padding 64 / 80 / 104 and margin 16 / 32 / 96. Confidence: medium. This is a design call, and the evidence can't settle it.
  2. Ratify D2 as worded in the verdict. Tokens stay invariant except the layout tier. A component that needs a different step at a breakpoint picks another fixed token, and the breakpoint comes from the breakpoint collection. Confidence: high.
  3. Ratify D3: variant (iii), generated, on BDS tokens only. Confidence: high.
  4. Ratify the --page-inset move (§4): it joins the layout tier and loses its density ladder. Confidence: high.

After ratification, the order is: the ADR (#2643), then the BDS generator and tokens, then resume brikdesigns#1890.

7. Method notes

  • Browser measurements used Playwright Chromium at deviceScaleFactor 1, 320–1920 CSS px. That setting doesn't emulate zoom, so zoom was modelled as a narrower CSS viewport.
  • The site samples are marketing homepages. The gap method adds two bands' padding together with any media margin, so only its ratios are used, never its absolute values.
  • Vendor quotes come from pages or source files fetched in this session. Anything else is marked as not verified.
