# Page header

<ComponentLinks slug="page-header" />

Composable page-level header that brings together BDS components: `Breadcrumb`, `Button`, and `TabBar`. No background by default — inherits from parent context; the opt-in `sticky` prop adds an opaque surface so it can pin on scroll.

## Variants

`PageHeader` is bimodal — symmetric with [`Sheet`](?path=/docs/containers-sheet--docs). When `mode` is set and no explicit `actions` slot is provided, the header auto-renders mode-appropriate actions. Explicit `actions` always overrides mode-driven auto-actions (mirrors `Sheet`'s `footer` override). When `mode` is unset, behavior is unchanged — no breaking change.

The canonical URL pattern for bimodal pages is `/{table}/[slug]` (read) and `/{table}/[slug]/edit` (edit) — see [Read-Mode Page](?path=/docs/containers-read-mode-page--docs).

### Read mode

`mode="read"` with `onEdit` → `[Edit]` (primary, pen icon).

<Canvas of={Stories.ReadMode} />

### Read mode on a server page

`onEdit` is a function, so it cannot cross the RSC boundary — a React Server Component would have to become a client component to pass it. `mode="read"` with `editHref` renders the same `[Edit]` button as a navigating `<a>`, keeping the page a server component.

| Page kind | Prop | Renders |
| --- | --- | --- |
| Client (`'use client'`) | `onEdit` | `<button>` calling the handler |
| Server (RSC) | `editHref` | `<a href>` navigating to the edit route |

`editHref` wins if both are passed. Edit-mode `onSave` / `onCancel` are inherently client — a server page needing them wraps its own client component.

Both paths render the same pixels, so `editHref` has no canvas of its own — the element is the difference, and it is asserted in `InteractionTestEditHref`.

### Edit mode

`mode="edit"` with `onSave` / `onCancel` → `[Cancel] [Save]` `ButtonGroup`. Toggle `saveLoading` / `saveDisabled` via Controls.

<Canvas of={Stories.EditMode} />

`actions` accepts any `ReactNode`; `PageHeaderActions` opts a header into a consistent destructive/secondary/primary hierarchy and size instead of a bare flex row. ## Patterns

### Tabs

The `tabs` slot carries the **lifecycle status** of the page's entity (Draft / Published / Archived). It does not carry an entity switch (that is the sub-nav rail beside the page), an attribute filter (that is a `FilterBar` in the body), or a view mode (that is a `SegmentedControl`). The full rule is [page chrome placement](https://design.brikdesigns.com/docs/build-standards/composition-layers#page-chrome-placement).

### Sticky

Set `sticky` to pin the header to the top of its scroll container as the body scrolls. It renders an opaque `--bds-surface-primary` background (so content passes cleanly beneath) and stacks at `--bds-z-page-header` — above page content and the section rail, below the shell top bar and overlays. Non-sticky remains the default — existing consumers are unaffected. The header sticks within the nearest scrolling ancestor, so that container — not the window — must own the scroll.

- **Offset** — `top` reads `--bds-pageheader-top`, which defaults to `0px`. A shell with a top bar sets `--bds-pageheader-top: var(--bds-shell-top-bar-height)` on an ancestor. Never set it on the header itself.
- **Focus visibility (WCAG 2.4.11)** — a sticky header can cover the element keyboard focus moves to. Give the scroll container `scroll-padding-top` equal to the offset plus the header's height, e.g. `scroll-padding-top: calc(var(--bds-pageheader-top) + 120px)` with the height your variant renders. Use the window's `html` element when the window scrolls.

### Condense on scroll

Set `condenseOnScroll` (with `sticky`) for a minimized header once the page has scrolled. Default `false` — existing consumers are unaffected, and without `sticky` the prop does nothing, because a header that scrolls away has nothing to condense.

| | Expanded | Condensed |
| --- | --- | --- |
| Breadcrumbs, subtitle, metadata | Shown | Hidden |
| Media, title, actions, tabs | Shown | Shown |
| Title | `size="lg"` (default) → `--bds-heading-xl`; `md` → `--bds-heading-md`; `sm` → `--bds-heading-sm` | Two steps down: `lg` → `--bds-heading-md`; `md` / `sm` → `--bds-heading-tiny` (the bottom of the scale — one step for `sm`) |
| Section gap | `--page-header-section-gap` (`--bds-gap-xl`) | `--bds-gap-md` |

- **When** — the header condenses once the page has scrolled a header height past the point where it pins, and expands again when scrolled back to the pin. Between the two it keeps its current state. The gap is deliberate: condensing shrinks the header and moves the content below it up, and a browser with scroll anchoring scrolls back by the same amount. Condensing exactly at the pin would let that correction carry the page back across the line, so the header would expand and the scroll position would be yanked.
- **Offset** — measured from `--bds-pageheader-top`, so a header pinned below a shell top bar condenses relative to the bar.
- **State** — `data-condensed="true"` or `"false"` on the header; absent when the prop is off. Style or assert against it.
- **Motion** — the title's `font-size` animates (`--bds-duration-md`, `--bds-ease-out`); the hidden slots snap. Under `prefers-reduced-motion: reduce` nothing animates.
- **Server components** — the prop is a boolean, so a React Server Component can pass it.
- **Sentinel** — the header renders a zero-height `<span aria-hidden>` immediately before itself to detect scroll position. In a flex or grid parent that sets `gap`, it counts as one more item.
- **`--page-header-section-gap`** — the condensed state sets it on the header, so a consumer override of that variable does not apply while condensed.

### Variants

`variant` fixes the header's shape for the page. No variant changes shape on scroll; `condenseOnScroll` is a separate opt-in that applies to any of them.

| `variant` | Renders |
| --- | --- |
| `full` (default) | Every slot |
| `compact` | Media, a `--bds-heading-xl` title (same as `full`), actions and tabs. `size` is ignored. |
| `tabs-only` | Tabs only; the title stays as a visually hidden `<h1>` |

## CSS Override API

Four component-scoped CSS variables on `.bds-page-header` tune the internal rhythm without forking the component. Override at any cascade level (theme file, `globals.css`, `style` prop). Defaults preserve the lean 0.57.0 shape.

| Variable | Default | Controls |
| --- | --- | --- |
| `--page-header-section-gap` | `--bds-gap-xl` (24px) | Gap between root sections (inner / metadata / tabs) |
| `--page-header-content-gap` | `--bds-gap-sm` (6px) | Gap between the title-row and the subtitle |
| `--page-header-actions-gap` | `--bds-gap-sm` (6px) | Gap between the content column (title + subtitle) and the actions column |
| `--page-header-padding-bottom` | `0` | Bottom padding below the header |
