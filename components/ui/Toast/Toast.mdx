# Toast

<ComponentLinks slug="toast" />

## CSS Override API

Component-scoped CSS variables exposed on `.bds-toast`. Set on a wrapping element to override without touching BDS internals.

| Variable | Default | Controls |
|---|---|---|
| `--bds-toast-shadow` | `0px 4px 12px 4px rgba(0,0,0,0.24)` | Elevation shadow on the toast surface |

```css
/* Example: softer elevation in an already-elevated panel */
.side-panel {
  --bds-toast-shadow: 0px 2px 8px rgba(0, 0, 0, 0.12);
}
```

## ToastProvider

Queue, stacking and auto-dismiss around `Toast`. Mount `ToastProvider` once near the app root, then call `useToast()` anywhere below it.

<Canvas of={Stories.Provider} />

```tsx
const { success, error, toast, dismiss } = useToast();

success('Changes saved');
error('Save failed', 'Please try again.');
const id = toast({ title: 'Uploading…', tone: 'info', duration: 0 }); // stays until dismissed
dismiss(id);
```

| Behaviour | Detail |
|---|---|
| Stacking | Bottom-center, newest last. `maxVisible` (default `3`) show at once; the rest queue. |
| Auto-dismiss | `duration` prop on the provider (default `4000` ms), overridable per toast. `0` keeps it until dismissed. The countdown starts when a toast becomes visible. |
| Pause | Hovering or focusing a toast pauses its countdown. |
| Urgency | `negative` toasts default to `assertive`; everything else is `polite`. Override per toast with `urgency`. |
| Motion | The slide-up entrance is disabled under `prefers-reduced-motion`. |

`useToast()` throws outside a `ToastProvider`.

## Notes

### Announcement priority

Toasts announce **politely** by default — `role="status"` with `aria-live="polite"`, which waits for a pause before speaking. That suits the confirmations and status updates most toasts carry.

Pass `urgency="assertive"` to escalate to `role="alert"` / `aria-live="assertive"`, which interrupts whatever the screen reader is saying. Reserve it for messages the user must act on immediately — unsaved work about to be lost, a session expiring.

`urgency` is **independent of `variant`**. A red `error` toast reporting a retry that already succeeded is still `polite`; the colour communicates severity to sighted users, the live region communicates interruption priority to screen-reader users, and those are different questions.

| `urgency` | `role` | `aria-live` | Use for |
|---|---|---|---|
| `polite` *(default)* | `status` | `polite` | Saved, copied, sent, background sync finished |
| `assertive` | `alert` | `assertive` | Data loss, session expiry, an action that must be undone now |
