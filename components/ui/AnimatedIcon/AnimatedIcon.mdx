# Animated icon

<ComponentLinks slug="animated-icon" />

Lottie-react wrapper for animated UI icon states. Consumers source Lottie JSON from [useanimations.com](https://useanimations.com), [lottiefiles.com](https://lottiefiles.com), or their own After Effects → Bodymovin exports and pass it via `src`.

## Variants

AnimatedIcon has no semantic-variant axis — every prop (`trigger`, `size`, `loop`, `label`) is a Control on the canvas above. Per [ADR-010 §components without a variant axis](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-010-storybook-axes-of-information.md), the `trigger` enum (`loop` / `hover` / `click` / `once`) lives in Controls rather than as separate stories because at-rest snapshots are visually identical across modes — trigger differences only manifest in motion.

<Canvas of={Stories.Default} />

- **`loop`** — continuous decorative motion
- **`hover`** — discoverable interaction hint
- **`click`** — feedback on activation
- **`once`** — entrance moment on mount

## Notes

> **Note** — `lottie-react` respects `prefers-reduced-motion` when `autoplay` is `false`. AnimatedIcon sets `autoplay` only for the `loop` and `once` triggers; `hover` and `click` are user-initiated, so motion-sensitive users hit them deliberately.

> **Note** — BDS does not ship a curated Lottie catalog. Each consumer brings its own animation JSON files. If you need a system-wide catalog (similar to the iconify-backed `Icons` reference), file a separate issue.

> **Note** — BDS supports React 18 and 19 for this component (`peerDependencies.react` is `>=18.0.0`). On **React 18 in development only**, `lottie-react` v3 makes React log `Unexpected return value from a callback ref` once per rendered animation: v3's internal `mergeRefs` returns a cleanup function from a ref callback, which is the React 19 contract, and React 18 discards it. Nothing leaks — `item.destroy()` runs from a `useEffect` cleanup, not the ref cleanup, and effect cleanups fire on unmount under both majors. Measured on React 18.3.1: lottie-web's registered-animation count goes 1 → 0 across unmount, asserted by `AnimatedIcon.unmount.browser.test.ts`. BDS silences that one warning in Storybook and its test runs; if you see it in your own React 18 app it is safe to ignore or filter the same way. Tracked as brik-bds#2029, filed upstream as [Gamote/lottie-react#140](https://github.com/Gamote/lottie-react/issues/140).
