# Status list

<ComponentLinks slug="status-list" />

A read-only list of tracked outputs. Each row shows a title, an optional description, and one of five states as a distinct icon plus a status badge. Each state maps to one tone:

| Status | Badge label | Tone | Icon |
| --- | --- | --- | --- |
| `complete` | Complete | positive | `ph:check-circle` |
| `in_progress` | In Progress | info | `ph:clock` |
| `not_started` | Not Started | neutral | `ph:circle` |
| `blocked` | Blocked | warning | `ph:warning` |
| `negative` | Failed | negative | `ph:warning-circle` |

 Rows are display-only: no click target, and labels are never struck through.

## Notes

> **Note** — A `negative` row can carry an `message`, rendered under its description in a `role="alert"` region so assistive technology announces the failure when it appears. The message is ignored on any other status.

> **Note** — Choosing between the list components. Use StatusList to *read* the state of each item. Use [`Checklist`](/?path=/docs/components-checklist--docs) or [`ChecklistGroup`](/?path=/docs/components-checklist-group--docs) when the user *toggles* completion, which strikes the label through. Use [`ProgressStepper`](/?path=/docs/components-progress-stepper--docs) for position in one linear flow, where a single active step decides which steps are complete or upcoming and there is no per-item negative state.
