# SyncedMediaSteps

<ComponentLinks slug="synced-media-steps" />

An ordered step sequence — a process, a how-it-works band — where the active step reveals its description and crossfades its media into a synced panel. Auto-advances while in view, pauses on hover and focus, and yields to a click.

## CSS Override API

| Variable | Default | Set by |
|---|---|---|
| `--bds-synced-media-steps-interval` | `var(--duration-autoplay)` (10s) | `interval` prop |
| `--bds-synced-media-steps-media-aspect` | `4 / 3` | CSS only |

```tsx
<SyncedMediaSteps steps={steps} interval="6s" />
```

The interval is deliberately one value read by two consumers: the countdown bar animates over it in CSS, and the component reads the *resolved* property back to set its advance timer. Overriding it in either place moves both, so the bar cannot drift away from the advance.

## Notes

> **Keyboard contract is the accordion pattern, not tabs.** Every step trigger sits in the page Tab sequence, per the [WAI-ARIA APG accordion pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) — "all focusable elements in the accordion are included in the page Tab sequence". A roving tabindex belongs to the tabs pattern; use `MediaTabs` when the items are peer categories rather than an ordered sequence.

> **Reduced motion.** Under `prefers-reduced-motion: reduce` autoplay is disabled in JS (a paused CSS animation cannot stop a timer), the countdown is hidden, and the media swap and description reveal are instant. The active step still reads correctly — statically.

> **Media is the consumer's responsibility.** Set real `alt` text on images, `loading="lazy"` where appropriate, and a poster frame on video. Inactive media stays mounted so the crossfade has both frames, but is held out of the accessibility tree and the tab order via `visibility: hidden`.
