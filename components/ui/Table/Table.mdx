# Table

<ComponentLinks slug="table" />

Data table with composable sub-components (`TableHeader` / `TableBody` / `TableRow` / `TableHead` / `TableCell` / `TableSubheader` / `TableActionsCell` / `TableSkeletonRow`, plus the typed cells `TableIconCell` / `TableTextCell` / `TableAvatarCell` / `TableImageCell` / `TableLogoCell` / `TableServiceTagCell`). Supports sorting, row selection, striped rows, size variants, and arbitrary cell content. Trailing `[View][Edit][⋯]` clusters compose via `<TableActionsCell>`; cell-level affordances (Name / FK / Actions) replace whole-row click — see [Read and edit conventions](https://github.com/brikdesigns/brik-client-portal/blob/staging/.claude/references/settings-ia.md#read-and-edit-conventions).

## Default

<Canvas of={Stories.Default} />

`striped`, `size` (`default` / `comfortable`, 72px cell height), `headerBorder` (off by default), `headerBorderWeight` (`md` default / `sm` to match the data-row divider), `roundedTop` / `roundedBottom` (outer corners, on by default), and `headerBackground` (`secondary` / `primary`) are all Controls on this story.

## Variants

Sortable headers (`sortable` + `sortDirection` on `<TableHead>`) and checkbox row selection (`selected` on `<TableRow>`) — both are sub-component props, so they live in a dedicated story rather than Controls.

<Canvas of={Stories.SortableWithSelection} />

A `<TableCell>` accepts any content. This table exercises the composition catalog in one place — `<TableIconCell>` for the icon-left name, `<TableTextCell>` for the two-line owner, then `<Tag>`, a status `<Badge>`, an inline `<TextInput>`, a `<Tooltip>` header indicator, and a `<TextLink>` inside plain cells.

<Canvas of={Stories.CellTypes} />

`<TableSkeletonRow>` fills a loading `<TableBody>` — pass `columns` to match the header and `cellWidths` (`'short' | 'medium' | 'long'`, cycles if shorter than `columns`) to hint per-cell placeholder width. It composes `TableRow` + `TableCell`, so it automatically inherits the parent `Table`'s `size` row height.

## Patterns

The trailing `[View][Edit][⋯]` cluster composes with `<TableActionsCell>` — it owns alignment, shrink-to-content width, and the `--gap-sm` rhythm, so consumers stop hand-rolling `style={{ textAlign: 'right' }}` on `<TableCell>`.

<Canvas of={Stories.WithActionsCell} />

The canonical read/edit row has three click-target classes — **Name** (`<TextLink>` opening the read sheet), **foreign-key cells** (`<TextLink>` opening the related entity's read sheet), and **Actions** (`<TableActionsCell>`). Read-only display cells (Status / Public / Featured) stay plain `<Badge>` or text.

<Canvas of={Stories.CellLevelInteractivity} />

### Forbidden — whole-row click

`onClick` on `<TableRow>` violates table cell semantics, breaks screen-reader expectations, and conflicts with cell-level affordances. Use cell-level click targets instead — the row should never carry the handler. The canonical replacement is the `CellLevelInteractivity` story above (Name / FK cells as `<TextLink>`, trailing actions in `<TableActionsCell>`).

`<TableSubheader>` groups body rows into labeled sections — drop it inside `<TableBody>` between row groups.

<Canvas of={Stories.WithSubheaders} />

### Typed cells

A cell earns a component when it renders the `<td>` itself *and* owns a cell-level concern — intrinsic width / alignment, an `aria` contract, or a row-density-coupled internal layout ([ADR-027](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-027-table-cell-layer-ownership.md)). Anything else is a primitive nested inside a plain `<TableCell>`.

`<TableIconCell>` pairs a label with a fixed 24px leading icon box, so labels align down the column even when glyph widths differ. `<TableTextCell>` stacks a primary line over an optional secondary — the avatar-less counterpart to `<TableAvatarCell>`, sharing its type ramp. Both appear in the `CellTypes` story above.

`<TableAvatarCell>` pairs an `Avatar` with a name and an optional secondary line (email / role). Initials render when no `src` is set; pass `primary` as a `<TextLink>` when the name should navigate.

<Canvas of={Stories.WithAvatarCell} />

`<TableImageCell>` renders a fixed square (1:1) thumbnail for a logo or product image — `fit="contain"` for logos (no crop), `fit="cover"` for product photos. Upload / edit wiring is consumer-side.

<Canvas of={Stories.WithImageCell} />

`<TableLogoCell>` is the name-referenced counterpart — a bundled brand `Logo` (`set` + `name`) in the same square footprint. Use it for payment methods, integrations, or bundled client marks; use `<TableImageCell src>` for per-tenant uploaded logos.

<Canvas of={Stories.WithLogoCell} />

`<TableServiceTagCell>` hosts one or more `ServiceTag`s — `variant="icon"` for icon-only classification, `variant="icon-text"` for a labeled tag.

<Canvas of={Stories.WithServiceTagCell} />
