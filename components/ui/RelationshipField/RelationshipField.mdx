# RelationshipField

<ComponentLinks slug="relationship-field" />

Orderable multi-pick control for a catalog-backed relationship — services on a plan, linked resources, team roles. Adds from `options`, removes, and reorders with up/down buttons. Array position **is** the persisted order (a `sort_order`-style column) — that's the deciding factor for reaching for this component over `MultiSelect` or `CatalogPicker` (see below).

## When to use RelationshipField vs. MultiSelect / CatalogPicker

| Component | Order matters? | Free-text additions? | Read mode |
| --- | --- | --- | --- |
| `RelationshipField` | **Yes** — array position is the saved value | No — pick from `options` only | Icon-text `ServiceTag` / `Tag` `TagGroup` |
| `MultiSelect` | No — selection is a set | No — pick from `options` only | N/A (edit-only chip control) |
| `CatalogPicker` | No — selection is a set | Yes — catalog pick or free-text, with `source` attribution | `AddableEntryList` read mode |

If reordering the selected items would change what gets persisted (a `sort_order` column, a rendered sequence), use `RelationshipField`. If the set of selections is all that's saved — order is incidental — use `MultiSelect` or `CatalogPicker` instead. See [ADR-031](../../../docs/adrs/ADR-031-relationship-field-ordering-and-read-mode-convention.md).
