# Filter bar

<ComponentLinks slug="filter-bar" />

Toolbar that pairs a result counter with one or more filter controls ([`FilterButton`](/?path=/docs/components-filter-button--docs), [`FilterToggle`](/?path=/docs/components-filter-toggle--docs), or any compatible child). Use above tables and lists to expose filtering plus a clear-all affordance.

Layout: `[search?] [title] [counter] ... [filter children] [clear?] [actions]`

## Actions slot

<Canvas of={Stories.WithActions} />

`actions` renders a `ButtonGroup` of secondary / outline buttons (or any node) flush-right, after the filter controls and clear button. It is intentionally **exempt from the narrow-own-width collapse** (ADR-019): shrink the bar below ~600px of its own width and the filter controls fold into the `Filters (N)` popover, but `actions` stays visible outside it — an action like "Assign service" must never hide behind a popover trigger. Filter-bar buttons are **never primary** and default to `sm` (`size` prop) — one step below the `md` page-header buttons, so the bar sits lower in the page hierarchy; `actions` children without their own `size` inherit it.

## Search slot

<Canvas of={Stories.SearchWithFilters} />

`search` takes [`SearchInput`](/?path=/docs/components-search-input--docs) props (one of `label`, `aria-label` or `aria-labelledby` is required) and renders the field at the start of the bar. This is **filter** mode in [ADR-049](../../../docs/adrs/ADR-049-search-modes-filter-lookup-global.md): the query narrows rows already on the page, in memory, and the consumer owns the query-to-rows logic — the bar only displays `filtered` and `total`.

- **Landmark** — with a search slot the bar is a `role="search"` landmark named by the bar's `aria-label` (`"{title} filter bar"` by default; override it when two bars share a page). `SearchInput` itself carries no landmark. A bar with no `search` claims none: a title + counter + filters row is not a page search.
- **Count** — the counter follows `filtered`, zero included. A visually hidden `role="status"` region, always mounted while the slot is present, announces `filtered of total` (`0 of 8 engagements`) so the change is heard.
- **Clear** — `onClear` shows the "Clear filters" button whenever `filtered < total`, and clears an uncontrolled field. For a controlled field (`search.value`), reset the query inside `onClear`; the bar owns no state.
- **Below 600px** — the field is not a filter control, so it stays inline while the controls fold into the `Filters (N)` popover (ADR-019).

## No filters

<Canvas of={Stories.NoFilters} />

`children` is optional. A collection with no filterable axes still uses a FilterBar for its title + counter — the controls row is dropped entirely, not rendered empty — so an unfilterable list never needs a hand-rolled heading row. With no controls row present, `actions` takes over the flush-right auto margin.

## Nested heading

<Canvas of={Stories.NestedHeading} />

`titleAs` picks the title's element (`h2` default, `h3` when the bar nests under a section that already owns the `<h2>`). It is a semantic switch only — both render at `heading-sm`.

## Variants

FilterBar has no semantic-variant axis — all variation (title presence, counter status, clear-button visibility, filter children) is exposed via Controls + the hook-driven Default story. See [ADR-010 §components without a variant axis](../../../docs/adrs/ADR-010-storybook-axes-of-information.md) for the framework.

<Canvas of={Stories.Default} />

State behavior to exercise:

- **Filtered** — pick an Industry or toggle "Active only" → counter switches to `activeStatus` color and reflects the filtered count
- **No title** — clear the `title` Control → bar collapses to counter + children
- **Clear button visibility** — automatic: appears when `filtered < total` AND `onClear` is provided; suppressed otherwise

## Notes

> **Note** — FilterBar is the canonical host for compositions of [`FilterButton`](/?path=/docs/components-filter-button--docs) and [`FilterToggle`](/?path=/docs/components-filter-toggle--docs). Don't reach for a manual flex row in consumer code; use FilterBar so the counter, clear-button placement, and aria-label all stay consistent.

> **Note** — The Default story embeds a `useState` + `useMemo` filter pipeline because FilterBar's defining behavior (filter → recount → clear-button-appears) requires real state. Consumers wire their own data source; the in-story hook is illustrative.

> **Note** — FilterBar does not expose a `disabled` prop. Filter children manage their own disabled state (e.g., `<FilterButton disabled />` greys out an individual filter). When the entire bar should be locked, gate at the consumer level (omit the bar entirely or render a read-only summary instead).

> **Note** — FilterBar is fluid (`width: 100%`) — it fills its container. The Default story constrains the canvas to 1200px to match a typical desktop list/table viewport. Consumers control width via their layout. The controls collapse into the `Filters` popover by the bar's own width, not the viewport's — see the actions slot above (ADR-019); a mobile "Filters" sheet/drawer is not a separate mechanism.
