# Button

<ComponentLinks slug="button" />

Triggers an event or action. A single unified component covering four render shapes via discriminated unions:

- **Text button** — `<Button>Save</Button>` (default)
- **Text link** — `<Button href="/docs">Read docs</Button>` (renders `<a>`)
- **Icon-only** — `<Button icon={<X/>} label="Close" />` (`label` required)
- **Icon link** — `<Button icon={<X/>} label="Open" href="/x" />`
- **Router link** — `<Button href="/x" linkComponent={Link}>Open</Button>` (pass `next/link`'s `Link` to keep client-side navigation; `linkComponent` replaces the `<a>`, so `href` is still required)

`IconButton` and `LinkButton` remain available as `@deprecated` thin wrappers around `Button` for backward compatibility — prefer the unified API in new code. Consumer migration is tracked separately before they're removed in a future minor.

## Variants

One prop picks the style: `variant`, from a curated list of ten ([ADR-033 § Amendments](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-033-naming-canon-one-word-per-concept.md#amendments), #3275). Every value is a complete style. The class is `bds-button--variant-{value}`. Switch it from the Playground's Controls rather than per-value stories (ADR-010 §components-without-a-variant-axis).

<Canvas of={Stories.Default} />

| `variant` | Use for |
|---|---|
| `primary` (default) | The main action on a surface |
| `secondary` | A supporting action — neutral fill |
| `outline` | A lower-emphasis action — border, no fill |
| `ghost` | The lowest emphasis — text only |
| `inverse` | A primary action on an inverse (dark) surface |
| `on-color` | A primary action on a brand-primary surface |
| `negative` | A destructive action — solid system red |
| `negative-outline` | A destructive action at outline emphasis — red text and border |
| `negative-ghost` | A destructive action at ghost emphasis — red text |
| `positive` | A confirming action — solid system green |

No other style ships. `secondary` has no negative or positive version because the token set has no tinted surface/text pair for it. `positive` has no outline or ghost version because a confirmation is never a low-emphasis action (default-deny, ADR-033 § 6).

State props (`disabled`, `loading`, `fullWidth`, `selected`) and composition slots (`iconBefore`, `iconAfter`) are also Controls in the Playground, not standalone stories — per ADR-010 Q2.

> **Note** — `selected` was previously a member of `ButtonVariant`; it is now a boolean state prop that layers on top of any variant. It defaults to `undefined`; once defined, the button also sets `aria-pressed` so it reads as a toggle (ADR-045). See [#615](https://github.com/brikdesigns/brik-bds/issues/615) for context.

### Retired spellings

These spellings still resolve at runtime and warn once. They are honoured for one minor, then removed:

| Retired | Use instead |
|---|---|
| `variant="destructive"` · `variant="danger"` · `tone="negative"` | `variant="negative"` |
| `variant="danger-outline"` · `variant="outline" tone="negative"` | `variant="negative-outline"` |
| `variant="danger-ghost"` · `variant="ghost" tone="negative"` | `variant="negative-ghost"` |
| `tone="positive"` | `variant="positive"` |
| `emphasis="inverse"` | `variant="inverse"` |
| `emphasis="on-color"` | `variant="on-color"` |

A retired `tone` or `emphasis` on a variant with no matching style (for example `variant="secondary" tone="negative"`) keeps the variant.

## Modes

The Playground covers most props via Controls. Icon-only mode is the exception: `icon` is a `ReactNode` (`control: false`), so it can't be reached from the panel and gets its own story below. Anchor mode *is* reachable — set the `href` Control on the Playground.

### IconOnly

<Canvas of={Stories.IconOnly} />

Icon-only mode requires `label` (announced by screen readers; the icon span is `aria-hidden`). Uses the same variant + size scale as text mode — only the content shape differs. Switch `variant` / `size` from the Controls panel.

### AsLink

Setting `href` renders the component as `<a>` instead of `<button>` — same visual styling, semantically a link. It's identical to the Playground with an `href` set, so there's no separate visual story; the `InteractionTestAsLink` play test guards that the anchor branch actually renders an `<a href>`.

## CSS Override API

Component-scoped CSS variables exposed on `.bds-button`. Set on a wrapping element or directly on the button to override without touching BDS internals.

| Variable | Default | Controls |
|---|---|---|
| `--button-active-translate-y` | `1px` | Downward shift on `:active` press |
| `--button-focus-outline-width` | `2px` | Focus ring stroke width |
| `--button-focus-outline-offset` | `2px` | Gap between button edge and focus ring |
| `--bds-button-primary-background` | `var(--bds-background-brand-primary)` | Primary fill. Set the `-hover` and `-pressed` variants with it |
| `--bds-button-primary-background-hover` | `var(--bds-background-brand-primary-hover)` | Primary fill on hover |
| `--bds-button-primary-background-pressed` | `var(--bds-background-brand-primary-pressed)` | Primary fill while pressed |
| `--bds-button-primary-color` | `var(--bds-text-on-color-dark)` | Primary label and icon ink |

```css
/* Example: flatten press effect in a toolbar context */
.my-toolbar {
  --button-active-translate-y: 0;
  --button-focus-outline-width: 3px;
}
```

```css
/* Example: a service-themed section re-skins every primary Button inside it.
   Values must be Semantic tokens, never raw literals (ADR-014). Hover and pressed keep the brand shades unless you set their hooks too. */
.service-section {
  --bds-button-primary-background: var(--bds-background-info);
}
```
