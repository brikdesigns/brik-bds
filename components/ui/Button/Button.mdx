# Button

<ComponentLinks slug="button" />

Triggers an event or action. A single unified component covering four render shapes via discriminated unions:

- **Text button** — `<Button>Save</Button>` (default)
- **Text link** — `<Button href="/docs">Read docs</Button>` (renders `<a>`)
- **Icon-only** — `<Button icon={<X/>} label="Close" />` (`label` required)
- **Icon link** — `<Button icon={<X/>} label="Open" href="/x" />`
- **Router link** — `<Button href="/x" linkComponent={Link}>Open</Button>` (pass `next/link`'s `Link` to keep client-side navigation; `linkComponent` replaces the `<a>`, so `href` is still required)

`IconButton` and `LinkButton` remain available as `@deprecated` thin wrappers around `Button` for backward compatibility — prefer the unified API in new code. Consumer migration is tracked separately before they're removed in a future minor.

## Variants

Three orthogonal props, one concept each (ADR-033 § 2). `variant` is the **form**; `tone` is the **valence**; `emphasis` is the **hue source**. They collapse to Controls on the Playground rather than per-value stories (ADR-010 §components-without-a-variant-axis).

<Canvas of={Stories.Default} />

| Prop | Values | Default |
|---|---|---|
| `variant` (form) | `primary` · `outline` · `secondary` · `ghost` | `primary` |
| `tone` (valence) | `negative` · `positive` | none |
| `emphasis` (hue source) | `inverse` · `on-color` | none |

### Combinations that ship

| | `primary` | `outline` | `secondary` | `ghost` |
|---|---|---|---|---|
| (no tone) | yes | yes | yes | yes |
| `tone="negative"` | yes — solid system red | yes — red text + border | **no** | yes — red text |
| `tone="positive"` | yes — solid system green | **no** | **no** | **no** |
| `emphasis="inverse"` | yes | **no** | **no** | **no** |
| `emphasis="on-color"` | yes | **no** | **no** | **no** |

A pairing that does not ship is dropped to its form with a one-time console warning, never half-styled. The reasons:

- **`secondary` + any tone** — `secondary` is a neutral grayscale surface fill; a negative or positive tint on it needs a surface/text pairing the token set has not minted. Add it in Figma first.
- **`positive` on `outline` / `ghost`** — `positive` confirms a completed action; no caller wants a low-emphasis confirmation, so default-deny (ADR-033 § 6) applies. The negative pair exists because a destructive action must be reachable at every emphasis rung.
- **`emphasis` on `outline` / `secondary` / `ghost`** — `inverse` and `on-color` each paint the solid fill; a transparent or bordered form has no fill for them to paint.
- **`emphasis` alongside `tone`** — both pick what colours the fill, so they cannot both win. `tone` takes it and `emphasis` is dropped.

State props (`disabled`, `loading`, `fullWidth`, `selected`) and composition slots (`iconBefore`, `iconAfter`) are also Controls in the Playground, not standalone stories — per ADR-010 Q2.

> **Note** — `selected` was previously a member of `ButtonVariant`; it is now a boolean state prop that layers on top of any variant. It defaults to `undefined`; once defined, the button also sets `aria-pressed` so it reads as a toggle (ADR-045). See [#615](https://github.com/brikdesigns/brik-bds/issues/615) for context.

### Retired spellings

These `variant` values resolve at runtime (`resolveRetiredValue`) and warn once. Per ADR-033 they're honoured for one minor then removed, and they are **not** members of the `ButtonVariant` type:

| Retired | Use instead |
|---|---|
| `variant="negative"` · `destructive` · `danger` · `danger-outline` · `danger-ghost` | `tone="negative"` |
| `variant="positive"` | `tone="positive"` |
| `variant="inverse"` | `emphasis="inverse"` |
| `variant="on-color"` | `emphasis="on-color"` |

An explicit `tone` / `emphasis` wins over the one a retired `variant` value implies.

## Modes

The Playground covers most props via Controls. Icon-only mode is the exception: `icon` is a `ReactNode` (`control: false`), so it can't be reached from the panel and gets its own story below. Anchor mode *is* reachable — set the `href` Control on the Playground.

### IconOnly

<Canvas of={Stories.IconOnly} />

Icon-only mode requires `label` (announced by screen readers; the icon span is `aria-hidden`). Uses the same variant + size scale as text mode — only the content shape differs. Switch `variant` / `size` from the Controls panel.

### AsLink

Setting `href` renders the component as `<a>` instead of `<button>` — same visual styling, semantically a link. It's identical to the Playground with an `href` set, so there's no separate visual story; the `InteractionTestAsLink` play test guards that the anchor branch actually renders an `<a href>`.

## CSS Override API

Component-scoped CSS variables exposed on `.bds-button`. Set on a wrapping element or directly on the button to override without touching BDS internals.

| Variable | Default | Controls |
|---|---|---|
| `--button-active-translate-y` | `1px` | Downward shift on `:active` press |
| `--button-focus-outline-width` | `2px` | Focus ring stroke width |
| `--button-focus-outline-offset` | `2px` | Gap between button edge and focus ring |

```css
/* Example: flatten press effect in a toolbar context */
.my-toolbar {
  --button-active-translate-y: 0;
  --button-focus-outline-width: 3px;
}
```
