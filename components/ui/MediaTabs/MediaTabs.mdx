# MediaTabs

<ComponentLinks slug="media-tabs" />

The tab case of switching between peer categories — the home "Services" and "Industries" bands. A [`TabBar`](?path=/docs/navigation-tabbar--docs) rail of peer labels, each revealing its description and crossfading its media into a synced panel. Auto-advances while in view, pauses on hover and focus, and yields to a click or keypress.

Reach for `SyncedMediaSteps` instead when the items are an **ordered sequence** (a process) rather than peer categories — that is the accordion pattern, this is the tabs pattern.

## CSS Override API

| Variable | Default | Set by |
|---|---|---|
| `--bds-media-tabs-interval` | `var(--duration-autoplay)` (10s) | `interval` prop |
| `--bds-media-tabs-media-aspect` | `4 / 3` | CSS only |

```tsx
<MediaTabs tabs={tabs} interval="6s" />
```

The interval is deliberately one value read by two consumers: the progress cue animates over it in CSS, and the component reads the *resolved* property back to set its advance timer. Overriding it in either place moves both, so the cue cannot drift away from the advance.

## Notes

> **Peer categories only.** This composite is for options the reader picks **between** — parallel, mutually exclusive, few. An ordered set the reader walks **through** is [`SyncedMediaSteps`](?path=/docs/containers-synced-media-steps--docs) instead, and past about five items or with a panel tall enough that mobile must stack it, that is the one that still works. The rule and its tie-breaks live in the [display-choice build standard](https://design.brikdesigns.com/docs/build-standards/display-choice).

> **Keyboard contract is the WAI-ARIA tabs pattern**, delegated to `TabBar`. The rail exposes exactly one tab in the page Tab sequence (roving tabindex); [Arrow / Home / End](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) move focus and activate — Left/Right when horizontal, Up/Down when `orientation="vertical"`. `TabBar` gains this contract only when its items carry `controls`, so existing label-only tab bars are unchanged.

> **Reduced motion.** Under `prefers-reduced-motion: reduce` autoplay is disabled in JS (a paused CSS animation cannot stop a timer), the progress cue is hidden, and the media swap and description reveal are instant. The active tab still reads correctly — statically.

> **Media is the consumer's responsibility.** Set real `alt` text on images, `loading="lazy"` where appropriate, and a poster frame on video. Inactive media stays mounted so the crossfade has both frames, but is held out of the accessibility tree and the tab order via `visibility: hidden`.
