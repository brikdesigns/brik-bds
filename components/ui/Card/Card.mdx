# Card

<ComponentLinks slug="card" />

Flexible content container. A default flexible content slot (no `layout`), plus four anatomy-driven arrangements via the `layout` prop: `stack` (vertical content card / `CardGrid` cell), `row` (horizontal content card), `metric` (compact stat), and `control` (settings / integration row). One flat slot set (`media` / `overline` / `title` / `children` / `action` / `badge`) serves all four ([ADR-038](https://github.com/brikdesigns/brik-bds/blob/main/docs/adrs/ADR-038-card-anatomy-over-preset-union.md)). The web-only `PricingCard` component is documented alongside as part of the Card family.

> **Deprecated** — the `preset` discriminator (`control` / `summary` / `display` / `display-row`) is superseded by `layout` (ADR-038). It still renders unchanged for existing consumers; new code uses `layout`.

> **Note** — Multi-card compositions (service grids, feature grids, blog rolls) live in the [`Card Grid`](?path=/docs/theming-blueprints-card-grid--docs) blueprint, not on this page. This page documents the Card primitive itself.

## Variants

The `layout` prop selects the arrangement. Default (no `layout`) gives a flexible `children` slot composable with `CardTitle`, `CardDescription`, and `CardFooter`. Each `layout` arranges the same optional slot set into a distinct shape.

The default shape also takes a `variant`: `outlined` (default, secondary border), `brand` (primary-color border), `elevated` (surface fill, no border, no shadow), `raised` (surface fill, no border, `--box-shadow-md` drop shadow), and `borderless`.

### Raised variant

`variant="raised"` — surface-primary fill, no border, with a cast `--box-shadow-md` drop shadow. The shadow-casting counterpart to the now-flat `elevated` (brik-bds#1146 / BACKLOG-493 removed `elevated`'s shadow so portal cards read flat). Use for a focal/lone card or a grid cell that needs a lifted, contained read.

<Canvas of={Stories.Raised} />

### Borderless variant

`variant="borderless"` — transparent fill, no border, no shadow. Use for cards placed on a colored surface (service-tier or brand-image background) where the `outlined` border ring reads as visual noise. The card inherits the parent surface rather than forcing its own.

<Canvas of={Stories.Borderless} />

### Leading media (avatar / image / logo)

The default shape takes an optional `media` prop that turns the card into a horizontal "media object" — an `Avatar`, a square 1:1 `Image`, or a bundled `Logo` on the left, with `children` stacked to the right. Pass exactly one of `media={{ avatar: {…} }}`, `media={{ image: {…} }}`, or `media={{ logo: { set, name } }}`. All size to the shared Avatar scale (`sm` 32px, `md` 40px, `lg` 48px, `xl` 64px) so they read at the same footprint. The avatar falls back to initials from `name` and can carry a presence `status`; the image takes `fit` (`contain` for artwork, `cover` for photos); the logo renders a full-color third-party / client brand mark. Mirrors the `TableAvatarCell` / `TableImageCell` / `TableLogoCell` media cells.

### Stack layout

`layout="stack"` — vertical content card and the malleable `CardGrid` cell. Optional top `media`, an `overline` eyebrow, `title`, a `children` body, and a bottom-anchored `action`. All slots are optional so one arrangement serves any content type — service, blog post, customer story, property listing, team bio. `variant` / `tint` set the surface for a cell on a colored grid.

<Canvas of={Stories.Stack} />

The `mediaTreatment` prop controls how the `media` slot relates to the card edge. `flush` (default) bleeds the media to the edge and pads only the body (`--padding-lg`) — the blog/story/product-grid look. `inset` frames the media and body together in a single `--padding-huge` inset — the service-card "card-vertical" look. Cycle it in the Controls panel on the story above.

### Row layout

`layout="row"` — horizontal content card: `media` on the left, the text column (`overline`, `title`, `children` body, `action`) on the right. Use for single-row sections where a vertical layout wastes horizontal space: Related Customer Story, Recommended Add-On, featured plan. Toggle `imageWidth` between `narrow` (25%), `standard` (35%, default), and `wide` (50%) — or pass a CSS length / percentage. Collapses to a vertical stack at ≤ 640px.

<Canvas of={Stories.Row} />

### Metric layout

`layout="metric"` — compact stat card: an `overline` label above a large `title` value, with an optional trailing `action`. Context-neutral — a revenue figure, an active-user count, a storage total. Pre-format the value; the card applies no numeric formatting.

<Canvas of={Stories.Metric} />

### Control layout

`layout="control"` — settings / integration row. Leading `media` (logo) + `title` / `description` on the left, (`connectionStatus` indicator + `action`) on the right. Use `actionAlign="top"` for long descriptions where the action should anchor to the upper-right corner.

The `connectionStatus` prop accepts `not-configured | connected | syncing | synced | error` and renders a status indicator in the trailing block, coexisting with the `action` slot; pass `lastSynced` for a timestamp beneath it. `connectionStatus` is a **state of one card, not a set of variants** — cycle it in the Controls panel on the story below rather than reaching for separate stories.

<Canvas of={Stories.Control} />

### Pricing (web)

`PricingCard` — pricing tier with title, price block, feature checklist, and call-to-action. The `highlighted` prop marks the recommended tier with brand surface treatment. Web surface only (`surface-web`).

> **Note** — `PricingCard` is a standalone component (`import { PricingCard } from '@brikdesigns/bds'`), not a `preset` on `Card`. It is documented here because it is part of the Card family. Its CSS is isolated to `surface-web` pages.
