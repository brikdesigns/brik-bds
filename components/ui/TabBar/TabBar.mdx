# Tab bar

<ComponentLinks slug="tab-bar" />

Horizontal tab navigation with four style variants: text, text-underline, tab (bordered bar), and box (filled). Supports on-color backgrounds and disabled tabs via Controls.

## Variants

- **`text`** (default) — plain labels with brand color for active tab; no indicator. Shown in **Default** above
- **`text-underline`** — `text` color behavior + per-tab brand-color underline below the active tab. Use for app-level page headers that want both the brand-active text emphasis and an underline indicator
- **`tab`** — bottom-border bar with neutral-color active text and a brand-color underline that sits over the bar's baseline border
- **`box`** — filled background for active, bordered for inactive

### Scrollable

`overflow="scroll"` keeps the rail on one row and scrolls it sideways when the tabs outgrow their container — the right choice below the tablet breakpoint, where a wrapped rail pushes the page body down. The active indicator and focus ring stay un-clipped. The default, `overflow="wrap"`, flows extra tabs onto a new row.

<Canvas of={Stories.Scrollable} />

## Patterns

A tab bar switches between sibling panels of one entity: its lifecycle status (in a `PageHeader`) or the sections of a settings page. It does not switch a view mode (that is a [`SegmentedControl`](/?path=/docs/components-segmented-control--docs)) and it does not narrow rows by an attribute (that is a [`FilterBar`](/?path=/docs/components-filter-bar--docs)); see [page chrome placement](https://design.brikdesigns.com/docs/build-standards/composition-layers#page-chrome-placement).

Real-world usage: settings page navigation where clicking a tab switches the active tab and its content.

## Notes

> **Tabs or accordion?** Ask what the *set* is, because both hide all but one panel and the rendered output does not tell you which was right. Options the reader picks **between** ("Healthcare / Legal / Retail") are peer categories — parallel, mutually exclusive, few — and get tabs. Steps the reader walks **through** ("Scope → Design → Build") are ordered, and an [`Accordion`](?path=/docs/containers-accordion--docs) keeps every label visible so the reader can see where they are. Past about five items, or when a panel is tall enough that mobile has to stack it, the accordion is the one that still works. The full rule, its tie-breaks, and the worked cases live in the [display-choice build standard](https://design.brikdesigns.com/docs/build-standards/display-choice).

> **A rail driving a media panel** is [`MediaTabs`](?path=/docs/containers-media-tabs--docs), which composes this tab bar with a synced media slot, in-view-gated autoplay, and the WAI-ARIA tabs keyboard contract — reach for it before hand-rolling the sync.
