# Breadcrumb

<ComponentLinks slug="breadcrumb" />

Navigation breadcrumb trail showing the current page location within a hierarchy. Toggle `separator` (`slash` / `chevron`) via Controls on Default.

A crumb trail, a trailing sibling-record switcher, and a per-crumb sibling-record switcher on any middle crumb can all coexist — see Patterns below.

Pass `linkComponent` (e.g. `next/link`) so linked crumbs route client-side instead of triggering a full-page reload. See [framework guides → client-side routing](/docs/getting-started/framework-guides).

## Variants

A deep trail is mobile-safe by default — no prop required. The trail wraps at
crumb boundaries instead of clipping, and any single label longer than its
container ellipsises. Below 768px the intermediate crumbs collapse behind a
single `…` (`Home / … / Amendment 4821`) whenever there are two or more of
them; they stay in the accessibility tree, so screen readers still announce the
full trail. Switch the **Viewport** toolbar global to Mobile (375px) and Tablet
(768px) to compare.

## Patterns

### Sibling-record switcher

Pass two or more `options` (plus a `switchLabel`) to render a caret after the
trail. It opens a menu of sibling records — another service in the same line,
another project on the same client — so users jump between them without
navigating back to an index. Fewer than two options renders no caret, and the
trail stays a plain breadcrumb. `onNavigate` routes the selection client-side;
without it BDS does a full-page navigation.

<Canvas of={Stories.WithSwitcher} />

### Per-crumb switcher

Any crumb — not just the trailing one — can carry its own `switcher`. The
"Acme Holdings" crumb below opens a menu of sibling clients, independent of
the trailing project-to-project switcher at the end of the same trail. A
trail can have neither, either, or both; each switcher keeps its own
open/close state.

### Search, filters and scope label

A long switcher menu is narrowed three ways, on the trailing `options` and on a
per-crumb `switcher` alike:

- **Search** — a labelled search box appears once the option count is greater
  than `searchThreshold` (default `8`; `0` always shows it). It matches the
  option `label`, case-insensitively, and resets each time the menu closes.
- **Filters** — pass `filters` (`{ id, label, facet, value }`) to render
  `FilterToggle`s, off by default. Turning one on keeps only options whose
  `facets[facet] === value`; the `current` option always stays visible. Give
  options a `facets` record to match against. Filtering is client-side — BDS
  fetches nothing.
- **Scope label** — `scopeLabel` names the list above it, e.g. "Clients with
  Online Business Listings".

Options may also carry a `hint` — secondary text under the label (the
industry, say). It is display only and not searched.

Search takes focus when the menu opens. Escape closes the menu and returns
focus to the caret from the search box or a toggle.

### Derive the trail from the nav

Declare the nav once as a `NavSection`, then derive both the `SubNavigation`
items and the breadcrumb from it. The trail is `Section / Item`; the item is
picked by longest path-prefix, so a detail page under `/settings/services/42`
still resolves to `Settings / Services`. Pass `trailing` for a record crumb on a
detail page. When nothing matches it returns `[]`.

```tsx
import {
  Breadcrumb,
  SubNavigation,
  breadcrumbTrailFromNav,
  subNavItemsFromNav,
  type NavSection,
} from '@brikdesigns/bds';

const SETTINGS_NAV: NavSection = {
  label: 'Settings',
  href: '/settings',
  items: [
    { label: 'Services', href: '/settings/services' },
    { label: 'Agreements', href: '/settings/agreements' },
  ],
};

<SubNavigation items={subNavItemsFromNav(pathname, SETTINGS_NAV)} />
<Breadcrumb items={breadcrumbTrailFromNav(pathname, SETTINGS_NAV)} />
```

Both helpers are pure and hook-free, and ship without the `'use client'`
banner, so a Server Component can call them directly with the pathname.
