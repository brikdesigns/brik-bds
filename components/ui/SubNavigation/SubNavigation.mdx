# Sub navigation

<ComponentLinks slug="sub-navigation" />

Second-column nav for app shells that pair a collapsed primary `SidebarNavigation` with a section-specific sub-nav. Internally renders `NavItem` per entry. For a single-sidebar shell, use `SidebarNavigation` directly. For the full two-column layout (collapsed primary + sub-nav + main), see **Layouts / app-shell**.

**Don't nest SubNavigation inside SubNavigation, or stack two on one route.** One section-nav column per shell — further drill-down is PageHeader's `tabs` (TabBar) or inline sections in the content column.

**Don't nest SubNavigation inside `PageContent`.** It is a **full-height sibling column of `Page`** — top flush to the content area, `bordered` divider running the entire height — not page content. Put it beside `Page`, with `PageHeader` + `PageContent` to its right; see the composed shell in **Layouts / app-shell → With Page**. Nesting it inside `PageContent` drops the rail below the header and breaks the two-column shell (brik-client-portal#3162).

## Sticky rail behaviour

At tablet width and up the rail is `position: sticky` and fills the viewport below the shell top bar, whatever the page content height. It scrolls vertically on its own only when its items overflow.

- **Offset** — `top` and the height deduction read `--bds-subnav-top`, which defaults to `var(--bds-shell-top-bar-height)`. A shell with no top bar sets `--bds-subnav-top: 0` on the rail or an ancestor.
- **Height** — `100dvh` minus the offset, with a `100vh` fallback for browsers without dynamic viewport units.
- **Layering** — `--bds-z-sticky`, below the shell top bar (`--bds-z-shell`).
- **Below the tablet breakpoint** (`--bds-down-tablet`) — it is no longer sticky or full-height. Items render as one horizontally scrolling row with a bottom divider; group headers sit inline in the row. See the **Mobile** story.

## Groups and dots

Give items a `group` string to render group headers; consecutive items sharing a `group` render under one header (`role="group"`). Items with no `group` render with no header, so flat `items` lists are unchanged. Set `dot` (`true` or a `Dot` tone) on an item for an attention cue. See **GroupedWithDots**.

## Routing

Pass `linkComponent` (Next.js `Link`, Remix `Link`) to render each item with a router-aware link (ADR-012), and/or `onSelect(item, event)` to handle a click yourself, for example `event.preventDefault()` then `router.push(item.href)`. `onSelect` does not fire for `disabled` items.
